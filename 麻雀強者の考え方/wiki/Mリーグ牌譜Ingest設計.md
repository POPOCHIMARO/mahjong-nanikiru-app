## 取得方式の調査結果

2026-06-14 時点では、ブラウザ自動操作なしで取得できる。

- トップページの HTML にシーズン一覧がある。
- シーズンページの HTML には `Loading...` が表示されるが、Next.js の埋め込みデータとして `seasonData` が含まれている。
- `seasonData` から、日付、ステージ、卓、試合番号、選手、`gameId`、試合ページ URL を復元できる。
- 試合ページの HTML には、各局の `https://tenhou.net/5/#json=...` リンクが直接埋め込まれている。
- `#json=` 以降を URL デコードすると、天鳳形式の JSON が得られる。

このため、現段階の優先ルートは「内部データ/API特定」に近い。ログイン、Cookie、NAGA、ブラウザ自動操作は不要。

## なぜブラウザ自動操作か内部データ/API特定が必要か

Webページには、大きく分けて二種類あります。

1. 最初から HTML に一覧が書かれているページ。
2. 最初の HTML は空に近く、ブラウザが JavaScript を実行してから一覧を表示するページ。

Mリーグ牌譜サイトのシーズンページは、通常の HTML 取得では `Loading...` のような表示しか取れません。これは、牌譜一覧そのものが後から JavaScript によって読み込まれている可能性が高いことを意味します。

この場合、全牌譜を集める方法は主に二つです。

- ブラウザ自動操作: 人間が見るのと同じようにページを開き、JavaScript 実行後の画面からリンクを集める。
- 内部データ/API特定: JavaScript が裏側で取得している JSON やデータファイルを見つけ、そこから直接リンクを集める。

初心者向けに言うと、通常の HTML 取得は「店の入口に貼ってある紙を見る」方法です。JavaScript 型のサイトでは、店に入った後に店員が奥から商品一覧を持ってきます。だから、入口の紙だけ見ても商品一覧がありません。ブラウザ自動操作は実際に店へ入って待つ方法で、内部 API 特定は店員が奥から持ってくる元の棚を探す方法です。

## 抽出するイベント

- 打牌選択: 手牌、ツモ、ドラ、巡目、点棒状況、候補打牌。
- リーチ判断: テンパイ時にリーチしたか、ダマにしたか、待ち、打点、巡目。
- 副露判断: 鳴ける牌が出たときに鳴いたか、スルーしたか、巡目、打点期待、形。
- 押し引き: 相手のリーチ・副露に対して、テンパイまたはイーシャンテンから危険牌を押したか。
- ベタオリ判断: 和了を諦め、安全牌を優先したと判断できる局面。

## 押し引き分析軸

- テンパイからどれだけ押しているか。
- イーシャンテンからどれだけ押しているか。
- 自身の打点期待が何点くらいから押しているか。
- 親か子か。
- リーチ相手が親か子か。
- 巡目。
- 危険牌の種類。無筋、筋、壁、ワンチャンス、ドラまたぎなど。
- 点棒状況。トップ目、ラス目、南場、オーラス条件。

## 副露判断分析軸

- 巡目の影響: 序盤、中盤、終盤で鳴き率や鳴きの質がどう変わるか。
- 打点の影響: 鳴いた後の期待打点が低いとき、高いときで判断がどう変わるか。
- 形の影響: 愚形解消、良形確定、役確定、守備力低下。
- 局面の影響: 親番、ラス目、トップ目、南場条件。

## NAGA連携

[[NAGA連携設計]] に従い、何切る局面について期待値最大選択との一致率を測る。ただし NAGA はログインや利用条件が関係するため、自動アップロード・大量解析の可否は利用規約と実画面で確認する。
