和了判定holdを最優先に調べる方針は妥当である。
ただし、原因分類の完了だけではholdを解除できず、固定定数の現行の合成規則は、実在する合法候補集合で確率の合計が1を超える。

## 2. 指摘

### R1 [P1] 「未分類0件」だけでは和了判定holdを解除できない

対象：3節、4節、9節（特に210行）、D32B-01とD32B-10。

9節の判定は、`win_legality.unclassified > 0` の場合だけ `win_legality_unresolved` を残す。
この条件では、924件をすべて `rule_unresolved` に分類しても、他のholdがなければ `eligibleForD33=true` になる。
分類の完了と、合法性を正しく判定できることは別である。

**修正条件：**

- 原因分類の完了に加え、修正対象の再検証合格と、残存例外の適用範囲を接続条件に含める。
- 残存例外について、D.3.3とD.3.4で遭遇した場合の処理を明記する。未対応状態を単に不合法として粒子の重み0へ落としたり、成功試行だけを平均したりしない。
- 上位設計の失敗時方針に沿って、該当判断をholdにする経路を検証する。
- 「未分類0件だが未対応例が残る」固定例を採用判定テストに追加する。

残存率の上限だけでは十分ではない。
全体では低率でも、槓後など特定の状態へ集中すれば、その判断への影響は大きくなる。
層別件数と適用範囲、遭遇時の処理を先に確定する必要がある。

### R2 [P1] ロンと大明槓が同時に合法な場合、固定確率の合計が1を超える

対象：7.1節（144〜152行）、D32B-06。

「成分の行動が合法な家では、その行動へ定数の確率を与える」をロンと大明槓へ同時に適用すると、設計書の参考値では次のようになる。

```text
P(ron) + P(daiminkan)
= 1 - 17/8399 + 32/5342
≈ 1.0039662153
```

同じ家でロンと大明槓が同時に合法な窓は、保存済み教師窓に18件あった。
次の例は和了判定がknownで、共同応答の学習マスクも有効である。

```text
windowId: mleague:2018-19:L001_S001_0009_02A:11:0:e147:discard_response
seat: 2
legal kinds: daiminkan, pon, pass, ron
winActionStatus: known
learningMask.jointKind: true
```

**修正条件：**

- 複数の固定成分が同時に合法な場合の合成順序を定義する。
- 例えばロン見送りを先に判定し、その条件下で大明槓を選ぶなら、`ρ`をその条件付き確率として定義し、推定分母も合わせる。
- 全固定行動の確率が個別の定数と一致するという現行の受入条件を、合成規則に合わせて修正する。
- D32B-06にロンと大明槓の同時合法例を追加し、正規化と残余分布を検証する。

### R3 [P1] 現在の件数比は、そのまま各家の選択確率にできない

対象：2.3節、7.1節（134〜152行）、D32B-09。
関連実装：[ev_policy_opponent.py](../tools/ev_policy_opponent.py) の `_support_diagnostics`、[ev_policy_observation.py](../tools/ev_policy_observation.py) の応答ラベル生成と共同応答解決。

公開結果として観測された行動と、優先順位によって公開されなかった各家の希望を区別する必要がある。
合法候補に観測行動が含まれるかの数え直しだけでは、この問題は解消しない。

全4期間の再集計では、大明槓合法機会のうち86席は公開結果がロンだった。
そこで大明槓を希望したかは観測できない。
一方で、他家のチー成立からロン見送りが確定するのに、現行のexactラベル限定集計では見送りに数えない例が1件あった。

```text
windowId: mleague:2024-25:L001_S019_0017_02A:10:0:e105:discard_response
seat: 1
legal kinds: pass, pon, ron
public resolution: seat 3 の chi
seat 1 label: censored
```

このルール実装ではロンがチーに優先するため、チー成立は席1がロンを選ばなかったことを意味する。

**修正条件：**

- 定数の推定にも共同応答尤度を使うか、選択が確定する機会の定義と、その範囲への限定を明記する。
- 観測不能な希望を「選ばなかった」と数えない。
- 公開結果の制約から確定できる見送りを、exactラベルの有無だけで落とさない。
- 推定値が0または1になる場合も含め、粒子重みに使う定数の境界処理を定義する。

南4局を入口から外すだけでは、親子、点差、リーチ状態による異質性を許容できる根拠にはならない。
また、推定期間を3期間へ絞ることと、対象局面を絞ることは別である。
搶槓へのε_ron流用は、搶槓の観測から推定した値とは区別し、追加のモデル仮定として扱う必要がある。

### R4 [P1] 現在の感度シナリオでは符号反転を見逃す

対象：7.3節（162〜173行）、D32B-08。

見送り率と大明槓率を同時に上下させるだけでは、EVへの影響が逆方向の場合に変化が相殺される。
例えば、正規化した二つの変動量x、yに対して、次の反例が成立する。

```text
ΔEV = 1 + 2x - 2y

(x, y) = (0, 0): ΔEV =  1
(x, y) = (1, 1): ΔEV =  1
(x, y) = (0, 1): ΔEV = -1
(x, y) = (1, 0): ΔEV =  3
```

これは実際のEVを推定した結果ではなく、同時上下だけでは符号の安定性を保証できないことを示す数値反例である。

Jeffreys上限は一定確率モデル内の標本不確実性を表す。
局面依存による偏りや、観測のない搶槓への転用誤差まで覆う感度範囲にはならない。

**修正条件：**

- 各定数を個別に変えるシナリオと、混合した上下端を追加する。
- D.3.3に使える正の下側シナリオを定義する。厳密な0を使う前向きシミュレーション用シナリオとは区別する。
- 標本不確実性と、局面依存や搶槓への転用というモデル仮定の不確実性を分ける。
- D.3.4では、各シナリオに対応するD.3.3の事後分布と将来方策を用いることを明記する。
- 符号反転率の採用閾値をD.4までnullにする方針は維持できるが、それを感度範囲の十分性の証明として扱わない。

### R5 [P1] 固定成分を倍率診断から外すと、既知の大幅な誤差を通せる

対象：8.1節（187行）、8.3節（198〜202行）、9節。

固定成分を倍率診断から除くと、従来の大明槓の約68倍という誤差も、その成分単独ではholdにならない。

```text
observed rate  ≈ 0.0000109
predicted rate ≈ 0.000742
absolute error ≈ 0.0007311 < 0.005
```

固定値にしたことは、予測の妥当性を保証しない。
また、他家ロンによる打ち切りがあるため、「定数ρで経験率に一致する」という記述は一般には成立しない。

**修正条件：**

- 合成後に応答の優先順位を解決した公開結果の率は、固定成分も診断対象に残す。
- 各家の合法時選択確率と、全応答窓に対する公開結果の率を混同しない。
- pilotで例外を認める場合も、誤差と未識別状態を残した条件付き接続として記録する。
- 定数と観測率を別欄に記録するだけで、診断上の失敗が消える仕様にしない。

### R6 [P2] 役の特徴は近似精度以前に定義が未確定

対象：6節（121〜124行）、D32B-04。

`toitoi_feasible`の「一定数」が未定義である。
続く`open_without_yaku_path`は未定義の`toitoi`を参照し、「どの経路も0でない」としている。
真偽値の`toitoi_feasible`を意味するなら、対々形が成立しやすい場合ほど「役の経路なし」になる逆転が起こる。

**修正条件：**

- 対々形の閾値、真偽の向き、固定面子の数え方を確定する。
- 暗槓と門前の区別を明示する。
- `open_without_yaku_path`の条件を、定義済みの特徴だけを使った式として記載する。
- D32B-04に経路の有無が反転する境界例を加える。

得点器を通さない近似特徴として使うこと自体は可能である。
ただし、特定の手掛かりがないことを、一般的な「役の経路がない」ことと同一視しない定義と評価が必要である。
