# フェーズD.3.0 実牌譜イベントと局実行器の入口監査

実行日：2026-09-07
実装：Sol / high
判定：D.3.0完了（入口合格、実行器標本2局は原牌譜の牌在庫不整合としてhold）

## 実装した境界

原牌譜tokenから正規化イベントと判断直前snapshotを作る独立アダプターを追加した。
この経路はD.1の`extract_round`を呼ばず、配牌、通常自摸、打牌、リーチ、チー、ポン、三種の槓を時系列で復元する。

同じイベントを`RoundState`へ適用する実行器アダプターも追加した。
記録済み牌は136牌の所定位置へ固定し、未記録位置だけを二通りの決定的な順序で補完する。
物理IDではなく牌種、赤、手出しとツモ切り、公開行動、局末点を照合する。

得点器の例外境界も修正した。
`no_yaku`だけを和了不成立として扱い、依存不備、入力破損、未対応応答は合法手なしやpassへ変換せず、監査を止める例外として外へ返す。
固定得点依存を読み込めない場合は局単位のholdではなく監査全体をfailにし、CLIも終了コード2を返す。

`audit-policy-runtime`は将来評価台帳とD.1入力manifestの一致を必須にし、未許可シーズンを開発入力へ追加できない。
出力は[policy-runtime-audit.json](policy-runtime-audit.json)へ保存する。
同JSONは実行時のPython版、`mahjong`版、実行器、得点器、アダプターのSHA-256も記録する。

## 局実行器の標本照合

出典キーをSHA-256順に並べ、重複なしで256局を選んだ。
標本は全8シーズンを含み、南4局以降を15局含む。
各局を二通りの未記録牌補完で実行した結果、254局は終局種別と局末点が一致し、補完による結果差は0局だった。

2局は原牌譜の観測牌を赤区別付き136牌へ割り当てられずholdにした。
該当箇所は`2018-19.jsonl`の58行目と`2025-26.jsonl`の3,655行目である。
並べ替えや赤牌への読み替えでは修復していない。

初回標本では、牌譜が列挙しない裏ドラslotへ任意の補完牌を置き、その牌を得点計算へ渡して2局の点差が補完順で変化した。
これはアダプターの誤りだったため、記録された裏ドラ表示牌だけを得点器へ渡すよう修正した。
修正後は補完順による点差差異が0局になった。

標本監査は全7,849局の実行器一致率を示さない。
全件で確認したのは判断入口とresult差分であり、局実行器は計算量を固定した256局で検査した。
CLIの`--runtime-limit 0`を指定すれば参照局を全件実行できるが、D.3.1開始条件にはしていない。

## 固定検証

Python 71件、JavaScriptエンジン78件、JavaScript UI 5件が成功した。

追加した固定例は次の境界を検査する。

- 独立snapshotと保存済み方策入力の一致
- 異なる未記録牌補完で記録済み通常イベントが不変
- アダプター経由のチー、ポン、暗槓
- 既存局実行器fixtureによる大明槓、加槓、宣言牌ロン、頭ハネ、流局の点棒保存
- `no_yaku`と、依存不備または状態破損の採点エラーの分離

```powershell
$env:PYTHONPATH=(Resolve-Path calibration/.dependency-cache/mahjong-2.0.0-py3-none-any.whl).Path
python -m tools.calibrate_ev audit-policy-runtime --runtime-limit 256
python -m unittest discover -s tests -p 'test_*.py'
node tests/engine.test.js
node tests/app.test.js
```

固定依存を通常環境へ導入済みなら、`PYTHONPATH`の指定は不要である。

実装にはSol / highを推奨する。
打ち切られた応答のラベル解釈に設計変更が必要になった場合は、Astra / highで再確認する。
