作成日：2026-09-28。改訂：2026-09-29（改訂1〜3）。設計：Opus 5.5。
状態：設計確定（改訂3、実装前）。[Astra/highの反証レビュー](PHASE_D33_ADVERSARIAL_REVIEW.md)のR1〜R7（改訂1）、改訂1への再レビューの4件（改訂2）、改訂2への再レビューの3件（改訂3）を反映した（15節）。[開発計画](d3-development-plan.json)のD.3.3へ反映済み（2026-09-29）。
上位仕様は [D.3設計](PHASE_D3_DESIGN.md) の6〜7節、直前の結果は [D.3.2bレポート](PHASE_D32B_REPORT.md) とする。
本書は、上位設計7.1節の基準SMCを縮小規模で実装して実牌譜での適用率を測り（上位設計7.2節）、その改良候補として制約付きMCMCを設計する。どちらを主推定器にするかは、測定後に3節の関門で決める。

## 1. 作業契約

- 依頼の理解：対象家の判断時点までの公開履歴と対象家の私有履歴に条件付けて、他家3人の伏せ手牌と未公開牌の配置の事後分布からサンプルを得る推定器（D.3.3）を設計する。D.3.2bで確定した固定定数、感度シナリオ、層別の限界を反映する。
- 完了条件：本書に、推定対象、潜在変数と目標密度、基準SMCの測定と関門、初期化、MCMCの移動と不変性・可逆性・到達可能性、尤度の差分計算とキャッシュ、感度シナリオの扱い、診断とhold、出力、pilot、実装単位、受入試験を記載し、ローカルリンクと数値の照合が通ること。
- 変更対象：本書、根拠のprobe（`calibration/probes/d33-feasibility/`）。
- 対象外：実行コード、テスト、モデル、アプリ。開発計画は3回の反証レビュー後に更新した。
- 想定リスク：MCMCが事後分布の一部の成分（例：国士）に閉じ込められても、診断が見逃すこと。教師用の実際の手牌が初期化や検証に漏れること。固定定数の感度シナリオが計算量で実行できず、黙って削られること。

## 2. 前提

### 2.1 入口条件（開発計画 `scope`）

対象家の通常自摸後の判断で、ツモ前1シャンテン、自家未リーチ、成立済み他家リーチがちょうど1人、南3局以前。
**判断時点までに、どの家にも副露と槓がない**（`priorCallsOrKans: false`）。
そのため、判断時点までの履歴は、配牌、自摸、打牌、リーチ宣言、各捨牌への全員パスだけで構成される。
推論入力は`dataset-opponent-v3/inference-prefixes.jsonl.gz`の32,019件（学習18,879、選択4,226、較正3,835、開発確認5,079）。

### 2.2 D.3.2bから引き継ぐもの

- 相手モデル：`model-opponent-v3`（`shared-hierarchical-softmax-v3-fixed-constants`）。θは固定し、D.3.3では学習しない。
- 固定定数と感度シナリオ：`fixed-components.json`の22シナリオ（D.3.3用、`zero`を除く）。各シナリオの事後分布は独立に作り、`base`からの重み替えで代用しない（D.3.2b設計7.6節、第2回反証S3）。
- `d33Conditions: ["fixed_component_sensitivity"]`：D.3.3の出力に感度診断を含めない実行は`held`で終える。
- 残存例外は0件のため、和了判定の検出器（`residual_win_legality_detector`）は不要。
- 限界：リーチ中の応答窓でポンの予測が観測の2〜4倍に過大（D.3.2bレポート8節）。判断時点までの履歴には「リーチ後に他家がパスした窓」が含まれるため、この偏りは事後分布に入る（9.3節で扱う）。

## 3. 基準SMCの測定と主推定器の関門

### 3.1 probeが示すこと

[probe](probes/d33-feasibility/riichi-tenpai-rate.json)で、学習期間の判断時点200件について、対象家から見えない牌のプールから13枚を一様に4,000回引き、テンパイの割合を数えた（seed 20260928、[スクリプト](probes/d33-feasibility/probe_riichi_tenpai_rate.py)をプロジェクト直下から実行）。

| 指標 | 値 |
|---|---:|
| テンパイ率の平均 | 0.0315% |
| 中央値 | 0.025% |
| 90%点 | 0.075% |
| 最大 | 0.3% |
| 4,000回中テンパイ0件の判断 | 69/200 |

出力には、seed、入力3ファイルのSHA-256、判断IDと判断ごとの成功数を保存した。
プールは公開履歴と対象家の私有履歴だけから数え、全家の私有履歴を持つ実行器側のプールと200件すべてで一致することを実行時に検査した。
実際のリーチ者の手（教師情報）は、抽出とは別の段で200件すべてテンパイと確認した。これは状態復元の検査であり、推定には使わない。

このprobeの結論は、**一様な13枚抽出は、初期化や提案として非効率**という点に限る。
観測で条件付けた基準SMCの生存率の上限ではない。
基準SMCは観測ごとに`q_e = K_e/G_e`で提案し、行動尤度で重みを更新し、再標本化する（上位設計7.1節）。
宣言直前の粒子は一様事前のままではなく、`P(T|C) ≤ P(T)`は一般に成り立たない。
判断時点と宣言時点では残数も違う。

### 3.2 基準SMCの縮小測定

上位設計7.2節どおり、基準SMCを実装し、実牌譜での適用率を測る。
履歴評価器（5.4節）はMCMCと共有する。

- 対象：12.1節のpilot 16判断、`base`シナリオだけ。
- 設定：粒子数256、1,024、4,096、各4独立反復。
- 記録：各観測段の`G_e>0`の粒子数、ESS、最大正規化重み、祖先数、再標本化の回数、`posterior_zero_mass`が起きた観測（家、巡目、イベント種別）。とくにrのリーチ宣言の段の`G_e>0`粒子数。
- 基準SMC自体の正しさは、D33-01の有限小例で正確な事後分布と照合する（D33-09）。

guided SMC（リーチ者の手を先に引く）やブロックresample-moveも候補だが、初期提案の補正、支持の網羅、逆向き履歴生成の密度を別に定義する必要があり、本書では設計しない。

### 3.3 関門

3.2節の結果で、MCMCの実装を続けるかを決める。判定は機械的に行う。

- 16判断×4反復のすべてで、N=4,096の基準SMCが`posterior_zero_mass`にならない場合：MCMCの実装に進まず、測定結果を添えて設計へ戻る。これは「基準SMCで足りる」という認定ではない。全粒子が消えなくても、祖先がほぼ1つになる、独立反復の間で待ち分布が大きく異なる、といった退化はあり得る。そのため、ESS、祖先数、反復間の差を添えた**未判定**として設計へ戻し、基準SMCの適用可否は設計の再判断で決める。
- N=4,096の16判断×4反復のうち1件でも`posterior_zero_mass`になる場合：その判断、段を記録し、MCMC（6〜8節）の実装へ進む。

判定に使うのはN=4,096の64反復だけである。N=256と1,024の結果は記録して報告するが、分岐には使わない（低い粒子数だけで失敗し、N=4,096では全反復が成功した場合は、第1分岐に当たる）。

MCMCを実装した場合に限り、基準SMCが成功した判断で、MCMCの事後分布と要約統計（rの待ち、フリテン率、ドラ枚数）を比べる（12.4節）。両者は独立な実装なので、国士などの成分の取りこぼしの検査になる。比較の前に、その判断の基準SMCの退化の診断値を確かめ、退化した反復を比較の基準にしない。

## 4. 推定対象と潜在変数

### 4.1 推定対象

対象家s、判断時点tについて、次の事後分布からサンプルを得る。

```text
B(z | I_t) ∝ p0(z) × H(z; I_t) × L_θ,c(z; I_t)
```

- `I_t`：対象家の配牌、tまでの対象家の自摸と行動、公開履歴（打牌の牌種・赤・手出し/ツモ切り、リーチ宣言、ドラ表示牌、点数）。
- `z`：未知の物理牌の配置（4.2節）。
- `p0`：136枚の公平なシャッフル。
- `H`：観測との整合（0か1、4.4節）。
- `L_θ,c`：他家の過去の行動の尤度（5節）。θはv3モデルの係数、cはシナリオの固定定数。

対象家の過去の行動には尤度を掛けない（上位設計6.1節）。局末の結果、t以後の他家の開示手牌、裏ドラは入れない。

### 4.2 位置と物理ID

潜在変数は、ラベル付きの位置へ物理牌IDを割り当てたものとする。「牌種」は牌種と赤の組を指す。

| 位置 | 牌種 | 物理ID |
|---|---|---|
| 他家jの配牌13位置 | 未知 | 未知 |
| 他家jの手出し窓の自摸位置 | 未知 | 未知 |
| 他家jのツモ切り窓の自摸位置 | 既知（打牌と同じ） | 同じ牌種の中で未知 |
| 未割当プール（残りの山、王牌の未公開位置） | 未知 | 未知 |

**打牌は位置を持たない。** 他家jの打牌は、jの配牌または自摸の位置にあった牌そのものである。
そのため、jの位置の牌種の合計は「判断時点の手牌13枚＋jの全打牌」に一致する。
手出し窓の打牌の牌種は、その時点のjの手中にあればよい（打牌整合）。手中のどの物理コピーを切ったかは尤度に影響しないので、潜在変数にしない。
プールは、136枚から対象家の既知の牌（配牌と自摸。対象家の打牌はこの中にある）、ドラ表示牌、他家3人の全位置を除いた残りである。
こうして、1枚の物理牌を過去の位置と河とで二重に数えない。

ツモ切り窓の自摸位置は牌種が決まっているので、移動の対象から除く。その物理IDは同じ牌種の中で一様であり、他の位置の分布に影響しない。
そこで、**鎖の状態空間は、ツモ切り窓の自摸位置の物理IDを初期化時に固定した条件付きの空間**とする。固定の仕方は、その牌種の物理IDから一様に選ぶ。
目標はこの物理IDに依存しないので、条件付きの目標の牌種水準の周辺は、元の目標と同じである。7.4節の到達可能性とD33-01(c)は、この条件付きの空間で主張する。

公平なシャッフルの下では、ラベル付き位置への物理IDの完全な割当はどれも同じ確率を持つ。
そのため、物理IDの交換を提案する移動（M1、M2）では事前分布の比が1になる。
状態を牌種の計数へ縮約して実装する場合は、この等確率が牌種の水準では重みになる。
移動する家の位置とプールの牌種の合計を`A_t`（牌種tごとに一定）とすると、牌種を付けた位置の並びの事前重みは`Π_t 1/pool_t!`に比例する。
配牌を多重集合として持つ場合は、さらに`Π_t 1/h0_t!`（h0は配牌の牌種の計数）が掛かる。M3とM4（7.3〜7.4節）はこの形を使う。

**2つの水準の対応。** 鎖の状態は、ラベル付き位置への物理IDの割当（物理水準）で持つ。M1とM2はこの水準で提案する。
M3とM4は、配牌の多重集合と手出し窓の自摸の牌種列（牌種水準）で提案し、次の条件付き復元で物理水準へ戻す。

復元は、その牌種状態に一致する**ブロック内の物理配置全体から一様に1つ選ぶ**操作であり、次の3段で実現する。

1. 配牌の多重集合を13の配牌位置へ並べる方法`13!/Π_t h0_t!`通りから、一様に1つ選ぶ。
2. 各牌種について、ブロック内のその牌種の物理IDから、配牌と手出し窓の自摸位置のその牌種の位置へ、一様に割り当てる（非復元）。
3. 残った物理IDすべてを、ブロック内のプール位置へ一様な順列で並べる。

3段目を省き、プールの牌種の並びを固定したまま同種の物理IDだけを一様にすると、物理水準の目標を保たない（再レビューの小例：物理牌`A₁,A₂,B`、手牌1位置・プール2位置で不変性誤差0.125。全順列にすると約2.78×10⁻¹⁷）。
各牌種状態に一致する物理配置の数は`w(x)`に比例し、目標密度は牌種水準の量だけに依存する。したがって、牌種水準で`w(x)`を使ったMHの後にこの一様な復元を行うと、物理水準の目標を保つ。
手出し窓で同じ牌種の物理コピーのどれを切ったかは、どちらの水準でも状態に含めない。

### 4.3 リーチ者の区別

入口条件により、他家のうちちょうど1人（r）がリーチ済みである。
rについて、リーチ宣言時点（宣言牌を捨てた後）の13枚を`T_r`とする。
rのリーチ後の打牌はすべてツモ切りなので、判断時点のrの手牌は`T_r`と同じである。

### 4.4 硬い制約H

1. 牌在庫：各牌種は4枚、赤5は各色1枚。
2. 打牌の整合：他家jの手出し打牌は、その時点のjの手中にあり、直前の自摸とは別の物理牌である（同じ牌種でもよい）。ツモ切り打牌は直前の自摸牌と同じ牌種。
3. リーチの合法性：`T_r`がテンパイ（門前、固定面子0）。点数と残り山の条件は公開情報で決まり、Hに入れない。
4. リーチ後の打牌：rのリーチ後の打牌はすべてツモ切り（観測と一致しなければ状態復元の誤り）。
5. 判断時点の手牌の大きさ：他家は13枚。

牌在庫以外の規則上の和了可否（役、フリテン）は、5節の尤度の側で扱う。
合法な和了を見送った履歴はH=0にせず、固定定数ε（正の値）の尤度を掛ける。
v3モデルの確率はsoftmaxで正、εも正なので、H=1の状態では`L>0`である。したがって目標分布の支持はH=1の集合と一致する。これはD33-07で数値として確かめる（対数尤度が有限）。

## 5. 目標密度の因子

### 5.1 他家の自己行動窓

他家jの各自摸後の判断で、jの手牌（zから決まる）と公開情報からjの視点を作り、v3モデルの合成方策`M_θ,c(a | view_j)`で、観測した行動aの確率を掛ける。

- 手出しの打牌：どの牌を切ったか（牌種・赤・origin）。
- リーチ宣言の打牌：`riichi_discard`。テンパイでダマを選んだ窓では`discard`の確率が掛かる。
- ツモ和了が合法だったのに打牌した窓：固定成分により`ε_tsumo`×残余分布。

### 5.2 他家の応答窓

各捨牌（他家または対象家）に対し、判断時点までは全員がパスした（入口条件）。
他家jごとに、その窓でのjの合法集合をjの手牌から決め、`P_θ,c(pass | view_j)`を掛ける。

- 合法集合が`{pass}`だけの窓は1。ほとんどの窓はこれにあたる。
- ポン・チー・ロンが合法なら、合成方策でのpassの確率。ロンが合法なら`ε_ron`の因子が入る。
- 対象家の応答は既知の操作で、因子を掛けない。
- 公開結果が「全員パス」なので、各家のpassの確率の積がそのまま共同応答尤度になる。実行器の共同応答の解決（`ev_policy_observation.py`）では、非passの希望がなければ公開結果はpassになる。頭ハネや鳴きの優先順位で複数の希望が同じ公開結果へ潰れる場合は、入口条件により判断時点までに現れない。

### 5.3 フリテンと和了合法性

フリテンは実行器（`RoundState._is_furiten`）と同じ3種類で扱う。

| 種類 | 条件 | 解除 |
|---|---|---|
| 捨牌フリテン | 待ち牌が自分の河にある | 待ちが変わるまで |
| 同巡フリテン | 和了牌を見送った | 自分の次の打牌 |
| リーチ後フリテン | リーチ後に和了牌を見送った | 局終了まで |

見送りの履歴はzによって変わる（例：rの待ちに当たる牌を他家が捨て、rがパスした場合、rはリーチ後フリテンになる）。
そのため、フリテン状態は判断時点までの履歴をjの視点で順に評価して決める。各家のフリテンは、その家の仮説手牌と固定した公開履歴だけで決まり、他家の実際の待ちを必要としない。
役の有無は、待ち牌が一致した場合だけ得点器（D.3.2b工程1で修正済みの`score_hand`）で判定する。

### 5.4 評価器の単位

zの変更は、変更された位置を持つ家の因子だけを変える。各家の視点には、その家自身の伏せ牌と固定した公開履歴だけが入るためである。
他家3人の事後分布は牌在庫を通じて結合しているが、尤度の評価は家ごとに分かれる。共有プールの整合（牌在庫）はHの側で保つ。
そこで、家ごとの「履歴評価器」を作る。入力はその家の伏せ牌の割当と公開履歴、出力はその家の全因子の対数和とフリテンの履歴である。
評価器は実行器と同じ規則を使うが、局全体の状態機械は回さない。
実行器との一致は受入試験D33-07で確かめる。基準SMC（3.2節）も同じ評価器の窓単位の計算を使う。

## 6. 初期化

MCMCは、H=1の状態から始める必要がある。
一様な13枚抽出はほぼテンパイにならない（3.1節）ため、構成的に作る。

1. **rの宣言時手牌`T_r`**：7.3節の生成器`g_r`（面子手、七対子、国士）で、在庫を超えないテンパイ形を作る。
2. **rの履歴の逆算**：7.3節の逆算で、手出し窓ごとに「直前の手＝後の手＋打牌−自摸」とする。自摸は後の手13枚の物理牌から一様に選ぶ（打牌と同じ牌種でもよい。別の物理牌であればよい）。配牌まで戻したとき在庫を満たせば成功。
3. **他家（リーチしていない2人）**：判断時点の手をプールの残りから一様に13枚選び、同じ逆算を行う。
4. **検査**：Hと尤度（5節）が正であることを確認する。失敗したら乱数を変えて繰り返し、試行回数か時間の上限（12.3節）を超えたら`init_failed`で`held`にする。

初期化に使う情報は4.1節の`I_t`だけで、教師用の実際の手牌は読まない。
初期化の分布は事後分布と一致しなくてよく、補正も要らない。ただし、そのためにはMCMCが必要な成分の間を移動できることが前提であり、それはM3とM4（7.3〜7.4節）が担う。
初期化の生成器をMHの提案に使うのはM3とM4だけで、そこでは提案密度を正確に計算する。初期化の出力をそのまま事後標本とは扱わない。
鎖ごとに異なるseedで`T_r`を作り直し、出発点を分散させる。
初期化の試行回数、所要時間、成功した`T_r`の系統（面子手、七対子、国士）を鎖ごとに記録する。成功率が系統によって違ってもよいが、記録は残す。

## 7. MCMCの移動

M1、M2（位置aを固定したもの）、M3（家jを固定したもの）、M4は、それぞれ目標密度`B(z | I_t)`に対する詳細釣合いを満たす。
1反復はこれらの順序付き合成（7.5節）であり、Bを不変にするが、全体としては一般に可逆ではない。受入試験はこの区別に従う（D33-01）。
受理確率は対数空間で計算する。

### 7.1 M1：物理牌の交換（基本の移動）

- 他家3人の、牌種が未知の位置（配牌と手出し窓の自摸）の集合Sから位置aを一様に選び、`U = S ∪ プール`のうちa以外から位置bを一様に選ぶ。aとbの物理牌を交換する。
- S、U、プールの大きさは交換で変わらない。a、bがともにSにある場合は選ぶ順序が2通りあるが、逆向きも同じく2通りなので、提案は対称である。
- 事前分布の比は1（4.2節）。受理確率は`min(1, B(z')/B(z))`で、変更された家（1人または2人）の因子だけを再計算する。
- 同じ牌種どうしの交換は状態を変えないが、候補から除かない。除くと、交換の前後で「aと牌種が違う候補の数」が変わり、提案が非対称になるためである。同じ牌種どうしの提案は受理比1の空移動として数える。除く場合は別の提案比が必要になる。

### 7.2 M2：rのテンパイを保つ交換

M1だけでは、rの手を変える交換のほとんどがテンパイを崩して棄却される。そこで、rの手を変える専用の移動を加える。

- rの牌種が未知の位置の集合`S_r`（配牌13位置と手出し窓の自摸位置。交換で変わらない固定の集合）から、位置aを一様に選ぶ。
  「宣言時点で手中に残る牌の位置」に限定しない。どの位置の牌種が宣言時点まで残るかは各位置の牌種の配置で決まり、交換によってその集合が変わり、提案が非対称になるためである。
- 交換先の候補集合`V(z, a)`を、「aと交換した結果がすべての硬い制約H（4.4節）を満たす」プール位置と他家（r以外）の伏せ位置とする。r自身の位置は含めない。
- `V(z, a)`が空なら、この提案は現状維持とする。空でなければ一様にbを選んで交換する。
- 同じ位置aから逆向きに戻る提案確率は`1/|V(z', a)|`になるため、受理確率は次のとおり。

```text
α = min(1, B(z')/B(z) × |V(z, a)| / |V(z', a)|)
```

`|V|`は交換前後で両方数える。aを固定した核ごとに可逆で、aを状態によらず確率`1/|S_r|`で選ぶ操作はその混合なので可逆である。
将来`V`にr自身の位置を含める場合は、同じ交換に至る複数の選択経路を数え直す。

### 7.3 M3：家ごとの履歴の再生成（必須）

**M1とM2だけでは、国士テンパイと他の系統の間を移れない。**
1回の交換は宣言時の手を高々1枚しか変えず、国士テンパイは么九牌を12種以上含むのに対し、面子手のテンパイは高々5種、七対子のテンパイは7種しか持てない。
既存の`shanten`で国士テンパイ157牌姿の1枚置換62,205通りを調べると、テンパイを保つ3,744通りはすべて国士の中に留まった（反証レビュー付録A）。
H=0の途中状態は受理できないので、交換を重ねても国士の成分から出られない。この場合、鎖を増やしてもburn-inを延ばしても、国士の割合は出発点の割合で決まる。
同じ種類の分断は、履歴の制約によって面子手の内部やリーチしていない家でも起こり得る。
そこで、家jの手と過去の自摸をまとめて作り直すMHを必須の移動とする。

**ブロック。** 家jの牌種が未知の位置とプールの位置を合わせたものをブロックとする。他の2家の位置は変えない。
ブロック内の牌種の合計`A_j`は移動で変わらない。
jの位置の牌種の合計は「判断時点の手h＋jの手出しの打牌`D_j`」である（4.2節）。

**提案。** 新しい状態x'を次の3段で作る。

1. **判断時点の手h'**：`h' + D_j ≤ A_j`（牌種ごと）を満たすまで生成器`g_j`から引き直す。上限回数に達したら現状維持とする。
   - rの`g_r`：系統を固定確率`π_reg, π_chi, π_kok`で選ぶ。面子手は、雀頭を34種から一様、面子4つを55種（刻子34、順子21）から独立一様に選んで14枚を作り、1枚を一様に除く。七対子は異なる7種を一様に選び、1枚を除く。国士は么九13種に么九1枚を一様に加え、1枚を除く。赤は、各色の5について、`A_r − D_r`に残る物理牌から超幾何分布で決める。
   - リーチしていない家jの`g_j`：`A_j − D_j`から13枚を一様に引く（超幾何分布）。
2. **自摸の逆算**：判断時点から遡る。ツモ切り窓では手は変わらない。手出し窓kでは、打牌前の手＝打牌後の手＋打牌、自摸は打牌後の手13枚の物理牌から一様に選び（牌種ごとの確率は`n_after(d)/13`）、自摸前の手＝打牌前の手−自摸。最後に残る13枚が配牌である。この逆算は常に打牌整合を満たし、打牌整合を満たす履歴はどれもこの逆算でちょうど1通りに作られる。
3. **物理水準への復元**：4.2節の条件付き復元（その牌種状態に一致するブロック内の物理配置全体から一様に選ぶ。プール位置の並びも含む）を行う。

**提案密度。** 配牌を多重集合、自摸を手出し窓の順の列として、牌種の水準で次のとおり。
逆算の一対一対応は、この牌種水準の表現（配牌の多重集合と自摸の牌種列）について成り立つ。どの物理コピーを切ったかという経路は状態に含めないので、数えない。

```text
q_j(x') = g_j(h') × Π_k n_after_k(d_k) / 13
```

`g_r(h)`は、hに至るすべての生成経路の確率の和である。
面子手の生成器は雀頭と面子を独立に選ぶので、同じ牌種を5枚以上含む14枚形も作る。その1枚を除いた13枚形は在庫を満たし得る。
そのため、和は**hの合法な待ち牌に限らず、除いた牌の牌種x（34種すべて）**について取る。h+xを枚数の上限なしで雀頭1つと面子4つに分ける各分解Dについて、次を足す。

```text
π_reg × (1/34) × (4! / Π_m mult_D(m)!) × (1/55)^4 × c_{h+x}(x) / 14
```

`mult_D(m)`は分解D内の同じ面子の重複数、`c_{h+x}(x)`はh+x中のxの枚数である。
既存の`waiting_tile34`は、すでに4枚持つ牌を待ちから除くので、この和には使わない。
固定例：`h = 1111234m 222p 333s`では、共通分母`34×55⁴×14`に対する分子は、4mを除く経路が48、1mが5枚の形から1mを除く経路が120で、合計168になる。合法な待ち（4m）だけの和では48となり、3.5倍の差が出る（再レビュー指摘1、独立な列挙で確認済み）。
七対子は`π_chi × 2 / (14 × C(34,7))`（生成する14枚は各牌種2枚までなので、除く牌はhの単独牌に限る）。国士は、h+xが国士の完成形になる各牌種xについて`π_kok × (1/13) × c_{h+x}(x)/14`を足す（国士の生成器は各牌種2枚までしか作らない）。
七対子と面子手の両方でテンパイの手は、両方の項を足す。
これに赤の超幾何確率を掛ける。
引き直しで失われる確率`1 − Σ_{h: h+D_j ≤ A_j} g_j(h)`は`A_j`だけで決まり、移動の前後で同じなので、受理比では相殺する。上限回数での現状維持も同じ理由で状態に依存しない。

**受理確率。** 目標の牌種の水準の重みは、4.2節から次のとおり。

```text
w(x) = Π_t 1/h0_t! × Π_t 1/pool_t!
α = min(1, [w(x') L(x') q_j(x)] / [w(x) L(x) q_j(x')])
```

H(x')=1は構成で保証される（他家の位置は変えず、`h'+D_j ≤ A_j`で在庫を満たし、rのh'はテンパイ）。
物理IDを牌種の中で一様に割り当て直す操作は、目標が牌種だけに依存するので、物理IDの水準の目標も不変にする。
家jを固定したM3は、ブロックに対する独立型MH（Metropolis-within-Gibbs）なので可逆である。

**使い方と限界。** 1反復に各家1回ずつ行う。受理率は低いと見込むが、M1とM2では越えられない系統間の移動を可能にすることが目的で、局所の混合はM1とM2が担う。
系統の確率は**すべて正**（`π_reg, π_chi, π_kok > 0`）でなければならない。例えば`π_kok = 0`なら、国士の分断が再び残る。正である限り、値は効率だけに影響し、正しさには影響しない。値はpilot前にmanifestで固定し、0を設定した実行は開始前に拒否する。
正しさはすべての経路の和の計算に依存するため、上記の固定例と、生成器の経験頻度と計算した密度の一致をD33-02で検査する。

### 7.4 M4：他家3人の同時再生成と到達可能性

M3は1家ずつなので、ある家の目的の形に必要な牌が別の家に固定されていると、その家を先に動かす必要がある。小例で`πP=π`を確かめるだけでは、可約な鎖の正しさは認定できない。
そこで、他家3人の未知の位置とプールをまとめて1つのブロックにする独立型MHを加え、到達可能性を構成的に保証する。

**ブロックと提案。** ブロック内の牌種の合計Uは移動で変わらない。手出しの打牌の合計を`D = D_r + D_j1 + D_j2`とする。

1. rの手`h_r`を、`h_r ≤ U − D`を満たすまで`g_r`から引き直す（上限回数に達したら現状維持）。赤は`U − D`に残る物理牌から超幾何分布で決める。
2. `j1`の手を`U − D − h_r`から13枚一様に引く。`j2`の手を`U − D − h_r − h_j1`から13枚一様に引く。この2段は常に成立する（`|U| − |D| ≥ 39`）。
3. 3家それぞれについて7.3節の逆算を行い、4.2節の条件付き復元で物理水準へ戻す。

提案密度は、7.3節の`g_r`（赤を含む）、2段の超幾何確率、3家の逆算の`Π n/13`の積である。
引き直しと上限回数による現状維持の確率は、Uと`D`だけで決まり、前後で相殺する。
受理確率は7.3節と同じ形`min(1, [w(x')L(x')q(x)] / [w(x)L(x)q(x')])`で、`w`の`Π 1/h0_t!`は3家分を掛ける。M4は独立型MHなので可逆である。

**到達可能性の論証（副露・槓なしの範囲）。**
対象は4.2節の条件付きの状態空間（ツモ切り窓の自摸位置の物理IDを固定したもの）である。M4のブロックはそれ以外の移動可能な位置すべてとプールなので、この空間の状態はブロック内の物理配置で決まる。

1. 条件付きの空間の支持の任意の状態yについて、`h_r(y)`はテンパイなので、ある牌種xでh+xがいずれかの系統の完成形になる。系統の確率がすべて正なので`g_r(h_r(y)) > 0`である。
2. 他の2家の手の超幾何確率と、逆算の各因子`n/13`も正である（逆算は打牌整合を満たす履歴をすべて作る）。復元はyの牌種状態に一致するブロック内の物理配置全体から一様に選ぶので、yの物理配置そのものも正の確率で得られる。したがって、どの状態xからでも、M4はyを正の確率で提案する。
3. H(y)=1ならL(y)>0（4.4節）なので、受理確率も正である。
4. 1反復の最後にM4を置くと（7.5節）、それより前の移動がどの支持状態へ移しても、そこからyへ正の確率で移る。よって1反復の遷移確率は、条件付きの空間の支持の任意の2状態間で正であり、鎖はこの空間で既約かつ非周期的である。
ツモ切り窓の自摸位置の物理IDまで含めた物理水準全体では既約ではない（同じ牌種の2つの物理IDがその位置と移動可能な位置にある状態と、両者を入れ替えた状態の間は移れない）。この2状態は牌種水準では同じであり、推定に使う量には影響しない。

この論証は正しさ（極限分布が目標であること）を保証するが、有限の反復で混ざる速さは保証しない。M4の受理率は極めて低いと見込み、実際の混合はM1〜M3に依存する。
そのため、系統の支持と訪問、M3とM4の受理回数を診断し（10.1節）、同じ系統の内部で鎖が一部だけを訪れる場合は診断でも検出できないことを限界として報告する。
有限小例では、論証の実装検査として、正の質量を持つ状態の遷移グラフの強連結性を列挙で確かめる（D33-01）。

### 7.5 1反復と鎖の長さ

1回の反復は、次の順序付き合成とする。

1. M1を`|S|`回（毎回a、bを一様に選ぶ）
2. M2を`|S_r|`回（毎回aを一様に選ぶ）
3. M3をr、リーチしていない2家の順に1回ずつ
4. M4を1回（到達可能性の論証のため、必ず最後に置く）

各段は目標を不変にするので、合成も目標を不変にする。1反復全体の詳細釣合いは要求しない。
burn-in、保存間隔、反復数は、pilot前にmanifestで固定する。
上位設計の粒子数格子に対応する反復数の格子を、10,000、40,000、160,000反復とする。
3つは独立な実行ではなく、同じ鎖を160,000反復まで走らせ、10,000と40,000の時点を途中経過として評価する。

## 8. 尤度の差分計算とキャッシュ

### 8.1 差分計算

1回の提案で再計算するのは、変更された家の履歴評価器だけである。
履歴評価器は、その家の自己行動窓（判断時点までに8〜15窓程度）と応答窓（他家の捨牌ごと、25〜40窓程度）を順に評価する。
応答窓の大半は合法集合が`{pass}`だけで、合法性の判定（ポンの対子、チーの順子、ロンの待ち）だけで済む。

### 8.2 キャッシュ

v3モデルの特徴と学習分布は固定定数に依存しないが、θと温度には依存する。
そこで、窓ごとの学習分布を、固定定数を合成する前の形で、モデル識別子ごとに保存する。

| キャッシュ | キー | 値 |
|---|---|---|
| 形の計算 | 既存LRU（牌姿、固定面子数） | シャンテン、改善牌mask |
| 窓の学習分布 | モデル識別子（`thetaId`、温度、モデルのハッシュ）、判断ID、窓の位置、家、その時点の手牌の牌種の計数、フリテン状態、自己行動窓では自摸牌の牌種 | 合法集合、固定種別の有無、残余候補上の学習分布、観測行動の添字 |

自己行動窓で自摸牌を鍵に入れるのは、同じ14枚でも自摸牌によって`drawn`と`concealed`の合法候補が変わるためである。
例として、同じ14枚`112346789m 1247p 東`で自摸牌を2pと1mに替えると、手牌の計数は同じでも合法候補は13と14になる（反証レビューR3）。
実装では、既存の`RoundFeatureState.cache_identity`と同じく、合法候補集合のハッシュも鍵に含めてよい。

シナリオの違いは、この保存値に定数を合成する段階だけで扱う（D.3.2bの`compose_probabilities`）。
同じモデル識別子を持つ22シナリオ・全鎖でキャッシュを共有する。9.3節のθ変種は別のモデル識別子を持ち、キャッシュを共有しない。
キャッシュは判断ごとに作り直し、判断をまたいで再利用しない（窓の位置が判断ごとに違うため）。
窓キャッシュにはプロセスごとのLRU上限（件数）を置き、値はpilot前にmanifestで固定する。
キャッシュの有無で対数尤度が一致することを受入試験D33-07で確かめる。

## 9. 感度シナリオとモデルの限界

### 9.1 固定定数のシナリオ

D.3.3用の22シナリオ（`base`、`oat_*` 6、`corner_*` 8、`chankan_assumption`、層別6）すべてについて、独立した鎖を走らせる。
層別シナリオは、各家の層（親子、リーチ、点差、巡目）を判断時点までの各窓で評価し、その家の定数を`constants_for_seat`で決める。
入口条件では判断時点までに搶槓の窓がないため、`chankan_assumption`は事後分布に影響しない。ただしD.3.4の将来方策との対応を保つため、事後分布の識別子は他と同じく独立に持つ（計算は`base`と同じ鎖の結果を共有してよい）。

### 9.2 シナリオ間の比較

各シナリオの事後分布について、次を`base`と比べて報告する。

- rの待ち：
  - 待ち集合（34ビット）の分布どうしの全変動距離
  - 牌種ごとの待ちの周辺確率`p_k = P(kが待ちに含まれる)`と、その差`|p_k − q_k|`の最大値
  - 周辺確率の和は1にならない（複数待ち）ので、周辺確率のベクトルに全変動距離の式を当てはめない
- rのフリテン率
- 他家3人の手牌のドラ枚数分布
- 他家のポン可能対子の数の分布（9.3節の偏りの影響を見るため）

標本から推定した値には、標本数、系列相関を考慮した実効標本数、希少な待ち集合による推定誤差を併記する。
採否の閾値はD.4で固定し、それまではnullとする。

### 9.3 リーチ中の応答窓の偏り（D.3.2bレポート8節）

v3モデルは、リーチ中の応答窓でポンを過大に予測する。判断時点までの履歴では、rのリーチ後に他家がパスした窓が必ずあるため、この偏りは「リーチ後に捨てられた牌の対子を持つ他家」の事後確率を低めすぎる方向に働く。

この偏りを事後分布への影響として測るため、診断専用のθ変種を1つ追加する。

- `theta_riichi_response_recalibrated`：`discard_response`で応答者から見たリーチ人数が1以上の窓に限り、チーとポンの種別スコアにバイアスβ_chi、β_ponを加える。較正期間（2024-25）の共同応答尤度で推定する。
- manifestに、βの探索範囲と境界、正則化の有無、対象窓の支持件数、温度との適用順序（温度を掛ける前のスコアに加える）、推定の失敗時にholdとする条件を固定する。
- 本変種は`base`の固定定数で1シナリオとして鎖を走らせ、9.2節の比較を報告する。
- 採用はしない。較正期間は温度の選択と共用するため、本変種の較正期間での適合度は独立な検証にならない。補正後の適合や事後分布の差を、性能改善の証拠と呼ばない。
- この診断は開発確認期間の層別結果を見て追加したものなので、開発確認期間を後で独立な採用判定に使い直さない。
- 変種のθは別の`thetaId`とモデル識別子を持ち、キャッシュ（8.2節）とD.3.4への受け渡しで通常のシナリオと区別する。

## 10. 診断とhold

### 10.1 診断

MCMCは正規化定数を推定しないため、上位設計の粒子法の診断を次のように置き換える。

| 上位設計の診断（SMC） | D.3.3の診断（MCMC） |
|---|---|
| ESS、最大正規化重み | 要約統計ごとのbatch meansによる実効標本数 |
| 祖先数 | 独立な鎖の数と、鎖ごとの出発点の`T_r`の形 |
| リーチ者の手牌signature数 | 標本中の`T_r`の異なる牌姿の数と、その鎖間の重なり |
| 独立反復の差 | 鎖間のsplit-R̂（rの待ち牌の周辺確率、他家のドラ枚数、フリテン率） |
| 正規化定数 | 推定しない（D.3.4では不要） |
| 重み0の原因 | 提案が棄却された理由の内訳（在庫、打牌整合、テンパイ、尤度） |

加えて、次の成分の診断を記録する。鎖間の一致だけでは、全鎖が同じ不完全な成分に留まる場合を検出できないためである。

- 系統の支持：`T_r`を面子手、七対子、国士の各系統にする割当が、牌在庫とrの打牌整合の下で可能か（他家の配置を固定しない在庫上の判定）。
- 系統の訪問：鎖ごとの各系統の滞在割合と、系統をまたいだM3とM4の受理回数。
- M3の家ごとの提案数と受理率、M4の提案数と受理率。

支持のある系統を一度も訪れない場合は、質量が小さいだけか、移動の失敗かを区別できない。この場合は数値を報告し、`chain_disagreement`と同じく閾値がnullの間は採用判定をしない。
これらの診断は系統の単位でしか分断を捉えない。同じ系統の内部やリーチしていない家の履歴で、全鎖が同じ一部だけを訪れる遅い混合は検出できない。極限での正しさは7.4節の論証が担い、診断はその実装と混合の速さの検査として扱う。
基準SMCが成功した判断（3.3節）では、両者の系統の割合を比べる。

移動の種類ごとの受理率、変更された家の分布、キャッシュの命中率も記録する。

### 10.2 hold理由

| 理由 | 条件 |
|---|---|
| `init_failed` | 6節の構成的初期化が予算内に成功しない |
| `chain_disagreement` | 鎖間のR̂、`T_r`の重なり、系統の訪問がpilot後に固定する閾値を満たさない（閾値がnullの間は数値を報告し、採用判定をしない） |
| `resource_budget_exceeded` | 12.3節の予算を超える。シナリオや鎖を黙って削らない |
| `fixed_component_sensitivity_missing` | 22シナリオのいずれかの鎖が欠けている |
| `rule_unresolved` | 履歴評価器が得点器の未知エラーに遭遇した（D.3.2b設計4.3節の3経路と同じ扱い） |
| `state_reconstruction_mismatch` | 状態復元の検査（リーチ後の打牌がツモ切りでない等）に失敗 |
| `posterior_zero_mass` | 基準SMC（3.2節）で全粒子の重みが0になった。MCMCでは使わない |

どのholdでも、一様配布への退避、成功した鎖だけの集計、失敗した判断の差替えはしない。

## 11. 出力

判断ごとに次を保存する。

```text
schemaVersion, decisionId, informationStateHash, privatePrefixHash
modelVersion, thetaId, fixedComponentsHash, scenarioId, beliefVersion
seeds, chains, iterations, burnIn, thin
samples: 各標本の他家3人の手牌（牌種・赤）、rの待ちとフリテン、同巡フリテン、一発の資格、
         未割当プールの多重集合（D.3.4で残り山の順序を一様に割り当てる）
diagnostics: 10.1節の全項目（系統の支持と訪問を含む）
holdReasons, runtime, cacheStatistics
```

標本は物理IDではなく牌種・赤で保存し、D.3.4で同じ条件付き残数から物理IDを割り当て直す。
キャッシュ鍵と出力の識別子には`informationStateHash`を使い、公開局面IDだけで判断を識別しない（上位設計10節）。

## 12. pilot

### 12.1 判断の選び方

学習期間の推論入力から16判断を、公開情報だけで層別して選ぶ（上位設計10節）。
層は、rのリーチ巡目（早・中・遅）と、rが親か子か、対象家が親か子か。
乱数seedと選ばれた判断IDを、実行前にmanifestへ固定する。失敗した判断を別の判断で補充しない。
基準SMCの縮小測定（3.2節）とMCMCは、同じ16判断を使う。

### 12.2 設定の格子

| 項目 | 基準SMC（3.2節） | MCMC |
|---|---|---|
| 規模 | 粒子数256、1,024、4,096 | 反復数10,000、40,000、160,000（同じ鎖の途中経過） |
| 反復・鎖 | 各4独立反復 | 4鎖（独立な出発点） |
| シナリオ | `base`のみ | 22＋`theta_riichi_response_recalibrated` 1 |

### 12.3 予算

MCMCの反復数は、最小格子だけで16判断×23シナリオ×4鎖×10,000＝14,720,000反復、160,000反復まで同じ鎖を延ばすと235,520,000反復になる。
予算は160,000反復までの全格子を対象にする。

初期の上限は次のとおり。

- pilot全体（基準SMCの測定、初期化、MCMCの全格子）の実時間：24時間
- プロセスごとのworking set：4 GiB
- 並列プロセス数P：マイクロベンチマーク後にmanifestで固定する。総メモリ4P GiBが12 GiB以下（このPCの物理メモリ約16 GiB）なので、Pは最大3
- 初期化：鎖ごとの試行回数と時間の上限をmanifestで固定する

単一プロセスで一様な所要時間と仮定すると、24時間に全格子を収めるには1鎖10,000反復あたり平均3.67秒以内が必要になる。最大の3並列でも、基準SMCと初期化の時間を除く前の段階で、平均約1.10ミリ秒/反復が必要である。これは予算の換算であり、実測速度ではない。**完走できる見込みは未検証**で、24時間は停止の上限として置く。

実装後、1判断・1シナリオ・1鎖・10,000反復のマイクロベンチマークを測る。M2の前後の`V`の列挙、M3とM4の提案密度の計算を含める。
ベンチマークは、pilotを始めてよいかの関門として扱う。実装開始の承認とは別である。
ベンチマークからの見積もり（全格子、基準SMC、初期化の合計）が予算を超える場合は、pilotを始めずに`resource_budget_exceeded`として設計へ戻る。途中まで走らせてから止める運用にはしない。
見積もりが予算内なら、その値をmanifestに固定してpilotを始める。実行中に予算を超えた場合も、反復数やシナリオを減らさず、`resource_budget_exceeded`で止めて設計へ戻る。
予算超過時の代替策は事前に決めない。結果を見て判断やシナリオを減らす退避策を持たないためである。

### 12.4 pilotで報告すること

- 基準SMCの判断ごとの`posterior_zero_mass`の有無と段、ESS、祖先数（3.2節）、関門の判定（3.3節）
- 判断ごとの初期化の成否、試行回数、所要時間、`T_r`の系統
- 反復数の格子ごとのR̂、実効標本数、`T_r`の牌姿の数と鎖間の重なり
- 系統の支持と訪問、M3とM4の受理率
- 移動ごとの受理率と棄却理由
- 基準SMCが成功した判断での、MCMCとの要約統計の比較
- 9.2節のシナリオ間比較と、9.3節のθ変種との比較
- 計算時間、キャッシュの命中率、メモリ

pilotは採否を決めない。閾値はD.4で固定する。

## 14. 受入試験

上位設計のD33-01〜05は粒子法を前提にしているため、MCMC用に置き換え、基準SMCの検査をD33-09として加える。

| ID | 固定例と合格条件 |
|---|---|
| D33-01 | 小さな有限例（未知牌10枚程度、他家1〜2人、リーチ者1人。テンパイの判定は系統を持つ縮小規則でよい）で、全潜在状態を列挙した正確な事後分布を作る。(a) M1、aを固定したM2、jを固定したM3、M4の遷移行列それぞれで、詳細釣合い`B(z)P(z→z') = B(z')P(z'→z)`を全状態対で確かめる。(b) 7.5節の1反復（順序付き合成）の行列で`πP=π`を誤差1e-12以内で確かめる（詳細釣合いは要求しない）。(c) ツモ切り窓の自摸位置の物理IDを固定した条件付きの状態空間（4.2節）で、1反復の遷移確率が正の質量を持つ任意の2状態間で正であり（7.4節の論証の実装検査）、定常分布が一意に正確な事後分布と一致する。M3とM4の復元でプール位置の並びを固定し同種IDだけを一様にした実装が、物理水準の`πP=π`の不一致で検出される。(d) M1とM2だけでは国士に相当する系統が孤立する例と、ある家の目的の形に必要な牌が別の家に固定される例を含め、M3とM4を外すと(c)が不合格になることを確かめる。(e) 系統の確率のいずれかを0にした設定は開始前に拒否される |
| D33-02 | (a) 事前分布の検査：打牌整合とテンパイを課さない（牌在庫だけの）例で尤度を1にし、定常分布の各未知位置の周辺が残数に対する超幾何分布と一致する。(b) 制約付きの検査：尤度を1、Hを課した例で、定常分布が`p0×H`を全列挙して正規化した分布と一致する（無条件の超幾何分布とは比べない）。(c) 変異の検出：M2の`|V|`補正を省く、M1で同じ牌種どうしの交換を除く、M2の位置aを「手中に残る牌」に限る、M3の生成経路の和や逆算の`n/13`を省く、面子手の経路の和を合法な待ち牌だけに限る、牌種の計数へ縮約して`Π 1/pool!`や`Π 1/h0!`の重みを省く、の各実装をD33-01または(a)(b)の不一致で検出する。(d) 実際の規則の`g_r`について、固定例`h = 1111234m 222p 333s`の面子手の分子が168（共通分母`34×55⁴×14`）になる。固定した`A_r`で生成器の経験頻度（固定seed、10^6回）と計算した密度が一致する（カイ二乗検定、有意水準はテスト内に固定） |
| D33-03 | 全標本で`T_r`がテンパイ、牌在庫と打牌整合を満たす。フリテンリーチ（待ちがrの河にある）を許す。rがリーチ後に和了牌を見送った履歴でリーチ後フリテンが立ち、以後の窓でロンが合法集合から消える。構成的初期化が教師用の手牌を読まない（教師データを差し替えても初期化の分布が同じ）。国士と面子手の両方が支持を持つ固定例で、尤度を1にしたときM3とM4が系統をまたぐ遷移を受理する |
| D33-04 | 1つの状態に閉じ込められた鎖（移動を全棄却させた例）と、出発点の異なる鎖が別の峰に留まる例で、R̂と`T_r`の重なりが悪化を検出する。M3とM4を無効にし全鎖を同じ系統から始めた例で、R̂が良好でも系統の支持と訪問の診断が未訪問の系統を報告する。閾値が設定されていれば`chain_disagreement`になる |
| D33-05 | `init_failed`、`resource_budget_exceeded`、シナリオ欠落、得点器の未知エラーを注入し、それぞれのhold理由になる。一様配布への退避、成功した鎖だけの集計をしない |
| D33-06 | 情報境界：他家の実際の伏せ牌、t以後の自摸、裏ドラ、局の結果を差し替えても、推定器への入力と標本の分布が変わらない |
| D33-07 | 履歴評価器の合法集合、フリテン、和了可否、対数尤度が、同じ割当を実行器（`RoundState`）で進めた結果と一致する（固定seedの無作為な割当1,000件）。H=1の割当で対数尤度が有限。キャッシュの有無で対数尤度が一致する。固定例：同じ14枚`112346789m 1247p 東`で自摸牌を2pと1mに替えた2状態が別の鍵になり、合法候補数13と14を返す。通常θとθ変種を交互に評価したとき、キャッシュの有無で結果が一致する。シナリオの合成が`model.with_fixed`での直接計算と一致する |
| D33-08 | pilotのmanifest（判断ID、seed、反復数格子、シナリオ一覧、予算、並列数、キャッシュ上限、M3とM4の系統確率（すべて正）、ベンチマークからの予算見積もり）が実行前に固定され、実行後に書き換えられていない。失敗した判断が補充されていない |
| D33-09 | 基準SMCをD33-01の有限例で走らせ、事後分布と正規化定数が正確な値とモンテカルロ誤差の範囲で一致する（固定seed）。全粒子の重みが0になる例で`posterior_zero_mass`を返し、数値を返さない |

- 予算：全格子の反復数、並列数と総メモリ、キャッシュ上限、初期化の上限、途中経過として延ばす方式を固定した（12.3節、8.2節、7.5節）。
