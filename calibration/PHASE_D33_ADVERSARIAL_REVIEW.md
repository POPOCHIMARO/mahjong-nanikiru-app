### R1 [P1] 国士系が閉じた成分になり、初期化の混合比が消えない

対象：6節153〜160行、7.3節189〜193行、10.1節260〜263行、D33-04（355行）。
確信度：高。

**何が起こるか。**
国士テンパイとそれ以外のテンパイの両方に正の事後質量がある入力では、M1とM2の鎖は全事後分布へ収束しない。
4本を単純にまとめた標本中の国士の割合は、事後確率ではなく国士から開始した鎖の割合で決まる。
burn-inや反復数を増やしても直らない。

**理由。**
宣言時の手牌の計数は、宣言までにrへ割り当てた牌の計数から、観測済みの捨牌の計数を引いたものになる。
固定位置間の1回の交換がこの手牌へ与える変化は、高々1枚の置換である。
同じr内の位置交換はその計数を変えず、他家またはプールとの交換でも高々1枚しか変えられない。

国士テンパイの13枚には、么九牌が12種類以上ある。
面子手のテンパイは、完成した4面子1雀頭から1枚を除いた形なので、異なる么九牌は高々5種類である。
七対子テンパイは6対子と単独牌からなり、異なる牌は7種類である。
国士から1枚または2枚だけを替えても么九牌は10種類以上残るため、別系統のテンパイへ直接移れない。
H=0の途中状態を受理できない以上、2枚交換を繰り返しても国士成分からは出られない。

既存の`shanten`で、国士テンパイ157牌姿から在庫4枚以内の非同種1枚置換62,205通りを検査した。
テンパイを保った3,744通りはすべて同じ国士集合内で、他の系統への遷移は0だった（付録A）。
この検査は実データの国士事後質量を測ったものではないが、移動の構造的な分断を示す。
履歴制約を加えると辺は減るため、分断を解消する方向には働かない。

**診断で見逃す経路。**
seedを変えても全鎖が通常手から始まれば、通常手の成分内でよく動き、R̂、牌姿数、鎖間の重なりが良好なまま国士質量を丸ごと落とせる。
逆に形の種類を強制的に分散させても、成分間の正しい混合比は得られない。
「異なる峰から始めれば検出できる」というD33-04だけでは、この前者を検査していない。
多鎖診断と分散した初期値が必要であることと、それが全体の探索を保証することは別である。[診断の一次資料](https://arxiv.org/html/1903.08008v5)

**修正案。**
pilotで不一致を検出してからM3を考える手順を改め、系統をまたぐ移動を実装契約に含める。
候補は、リーチ手牌と必要な過去自摸を同時に再生成するブロックMHであり、逆算時の分岐、同じ牌姿へ至る複数の構成経路、再試行の扱いまで含めた提案確率が必要になる。
6節の生成器から無補正で再スタートするだけでは代替にならない。
成分別に推定するなら、成分の相対質量を別に推定する方法が必要である。

受入試験には、正の目標質量を持つ状態の遷移グラフの連結性、国士を含む異なる系統間の移動、全鎖が同じ不完全な成分だけを訪れる反例を追加する。
小例で`πP=π`だけを確認しても、可約な鎖の正しさは認定できない。

### R2 [P1] probeのテンパイ率を基準SMCの生存率の上限として使えない

対象：3節34〜51行。
確信度：高。

probeが測っているのは、判断時点の可視牌を除いたプールから13枚を一様に引いたときのテンパイ率である。
一方、[上位設計7.1節](PHASE_D3_DESIGN.md)の243〜275行は、観測ごとに`q_e = K_e/G_e`を用い、行動尤度で重みを更新し、ESSに応じて再標本化する。
宣言直前の粒子は、初期の一様事前のままではない。
リーチ観測に対しても、その1イベントで可能な未知自摸と行動を列挙する。

同じ確率空間でも、追加条件Cについて成立するのは`P(T∩C) ≤ P(T)`であり、`P(T|C) ≤ P(T)`ではない。
履歴への条件付けと行動尤度による選別が、テンパイ直前の粒子を増やす場合を排除できない。
さらに、probeは判断時点の残数を使うため、宣言時点との残数の違いもある。
したがって48行の「上限」と50行の「ほぼ全判断がposterior_zero_mass」は、この実験からは導けない。

数値自体も、独立な一様試行という仮定に限れば、`p=0.000315, N=4096`で0件となる確率は`(1-p)^N ≈ 0.27515`である。
これも実際のSMCの失敗率ではない。
平均率を使ったこの計算だけから、200判断それぞれの失敗率は復元できない。

**修正案。**
probeの結論を「一様13枚抽出は初期化として非効率」に限定する。
方式変更の証拠には、上位設計どおりの小規模SMCで宣言直前の`G_e>0`粒子数、ESS、祖先数、失敗箇所を測るか、履歴で重み付けされた粒子分布に対する別の有効な上界が必要である。
SMCの全件実装を必須とする指摘ではないが、未測定の基準方式を「実行不能」と認定して省略してはいけない。

guided SMCやブロックresample-moveも比較候補になる。
ただし、リーチ手を先に引く方法では初期提案の補正、支持の網羅、逆向き履歴生成の密度を明示する必要があり、現資料からMCMCより優れるとは判定できない。
一段先提案にも過去経路の退化が残るという上位設計の懸念は妥当である。[SMCとブロック更新の一次資料](https://www.stats.ox.ac.uk/~doucet/doucet_johansen_tutorialPF2011.pdf)

### R3 [P1] キャッシュが異なる合法集合と異なるθの確率を混同する

対象：8.2節211〜219行、9.3節247〜250行。
確信度：高。

窓の鍵は「判断ID、窓、家、手牌の牌種と赤の計数、フリテン状態」だが、自己行動窓の自摸牌が含まれていない。
同じ14枚でも、自摸した牌が単独牌か、同種牌をすでに持っていた牌かによって、`drawn`と`concealed`の合法候補が変わる。
既存実装は[意味上の行動への変換](../tools/ev_policy_observation.py)の335〜377行で両者を区別し、[相手モデル](../tools/ev_policy_opponent.py)の895行で`origin_drawn`を特徴に含めている。

既存の`RoundState`と`semantic_self_actions`を使い、同じ14枚`112346789m 1247p 東`で自摸牌を2pと1mに替えて比較した。
手牌の計数は同一、観測した手出しの東切りはどちらも合法、得点判定状態はどちらも`known`だったが、合法候補数は13と14になった。
打牌種別だけの一様な残余分布でも、東切りの確率は1/13と1/14になり、同じキャッシュ値を使えない。
この2状態は配牌と自摸を入れ替えれば構成できるため、単なる牌在庫違反の例ではない。

加えて、9.3節はθを変更したシナリオを導入するが、8.2節の値は「特徴」ではなく既にθを適用した「学習分布」である。
そのキャッシュを全シナリオで共有すると、`thetaId`を分離しない限り、診断専用の補正が消えるか通常シナリオへ漏れる。
固定定数だけの22シナリオ間の共有はこの問題に当たらない。

**修正案。**
自己行動用の鍵へ自摸牌の牌種と赤、またはその情報を含む合法候補集合のハッシュを追加する。
既存の`RoundFeatureState.cache_identity`も741〜753行で合法候補集合を識別している。
確率を保存する層には`thetaId`と温度を含むモデル識別子を付けるか、θ非依存の特徴だけを共有して確率を別計算する。
D33-07には上記の自摸牌衝突と、通常θ、補正θを交互に評価したときのキャッシュ有無一致を固定例として入れる。

### R4 [P2] 尤度を1にしても無条件の超幾何分布には戻らない

対象：D33-02（353行）。
確信度：高。

目標密度は`p0(z)H(z)L(z)`なので、`L=1`にすると残るのは`p0(z)H(z)`である。
リーチのテンパイと打牌整合を条件にした分布の周辺が、無条件の超幾何分布と一致する必要はない。
例えば`A,A,B,C`から位置に非復元抽出し、硬い制約を「第1位置はA」とすれば、尤度が1でもその位置のA確率は1であり、無条件の1/2とは異なる。
現条件では正しい実装を不合格にする。

**修正案。**
事前分布の検査では、既知の固定位置を除く抽出先についてHを恒等的に1にし、残数に対する超幾何分布と照合する。
制約付きの検査では、`p0H`を全列挙して正規化した分布と照合する。
この2試験を分け、後者では目標分布の不変性と遷移グラフの連結性を別々に検査する。

### R5 [P2] 1反復全体の詳細釣合いを要求すると正しい逐次合成を落とす

対象：7節164行、7.4節197行、D33-01（352行）。
確信度：高。

M1、M2をそれぞれK1、K2とすると、7.4節の自然な読みは、1反復が`K1^|S| K2^|S_r|`という順序付き合成である。
どちらもπを不変にすれば合成もπを不変にするが、可逆な核の順序付き合成は一般には可逆でない。
各提案で位置aをランダムに選ぶだけでは、この性質は変わらない。
したがって、D33-01の「M1とM2を合わせた遷移行列」が1反復を意味するなら、全状態対の詳細釣合いを要求する試験は誤っている。

72状態の小例では、M1、M2、両者の固定確率混合の詳細釣合い誤差は`8.7e-19`以下だった。
一方、`K1²K2`は不変性誤差`6.94e-18`に対し、詳細釣合い誤差`1.4449959e-3`となった（付録B）。
この結果はMCMC推定が誤るという指摘ではなく、正しい不変核を誤った試験で拒否するという指摘である。

**修正案。**
個々のM1、固定aごとのM2、または固定確率混合に詳細釣合いを検査し、1反復全体には`πP=π`を検査する。
1反復も可逆にしたい場合は、移動の種類も状態非依存の確率で選ぶ混合核などを明示する。
「混合」と「順序付き合成」のどちらをD33-01が作るのかを固定する。

### R7 [P2] 待ち牌の周辺確率ベクトルには通常の全変動距離を適用できない

対象：9.2節234行。
確信度：高。

牌種kについて`p_k=P(kが待ちに含まれる)`とすると、複数待ちがあるため`Σp_k`は1にならない。
このベクトルへ通常の`0.5 Σ|p_k-q_k|`を適用しても、確率分布間の全変動距離にはならない。
国士13面待ちに質量1の分布と、その13牌の1つだけの待ちに質量1の分布では、この式は6になる。
本来の全変動距離は高々1である。
総和で正規化すれば別の量になり、待ちの広さの差を失う。

**修正案。**
34ビットの待ち集合そのものの分布を比較して全変動距離を定義するか、各牌種のBernoulli周辺間の差`|p_k-q_k|`とその最大値などを報告する。
全変動距離を標本から推定する場合は、標本数、系列相関、希少な待ち集合による推定誤差も併記する。

### M1とM2の受理則の導出

M1でa、bがともにSなら、異なる物理割当へのその交換の提案確率は`2/(|S|(|U|-1))`である。
bがプールなら`1/(|S|(|U|-1))`になる。
位置の所属は交換しても変わらないため、逆向きも同じ確率である。
同じ牌種と赤の交換を数えたままにする設計は正しい。

M2はaを固定した核として考える。
候補bはr以外の伏せ位置またはプールに限られるので、交換後も同じ位置aからbとの逆交換を提案できる。
H(z)=H(z')=1ならbは逆向きのVにも入る。

```text
q_a(z'|z) = 1 / |V(z,a)|
q_a(z|z') = 1 / |V(z',a)|
q_a(z|z') / q_a(z'|z) = |V(z,a)| / |V(z',a)|
```

よって184行の式は正しい。
aを状態非依存の`1/|S_r|`で選ぶ操作は、これらの可逆核の混合なので可逆である。
Vが空の核は自己遷移だけとなり、詳細釣合いを壊さない。
将来bへr自身の位置も含める場合は、同じ交換に到達する複数の選択経路をどう扱うかを再確認する必要がある。

### 物理IDと初期化で確定しておくべき表現

「同種物理牌を同じ状態とみなす」を、尤度の同値性として扱うのか、MCMC状態を実際に縮約するのかを明記する必要がある。
13配牌位置と過去自摸位置を保持したラベル付き状態なら一様順列の事前比は1である。
実装で手牌を計数に圧縮し、未知プールも多重集合へ縮約する場合は、落とした位置とコピーの多重度を目標密度または提案分布に反映しなければならない。

特に84行の「公開済み打牌はプールから除く」は、終点の残数から除くという意味なら妥当だが、手出し牌は過去の配牌または自摸位置のどこかを占めていた同じ物理牌である。
そのIDまで過去位置への割当候補から除けば、打牌整合を作れない。
6節の逆算で打牌を戻す操作と4.2節の固定位置を対応させ、1枚の物理牌を過去位置と河で二重消費しない表現を図または小例で確定することを求める。
現文だけから、物理IDの採用そのものに必ず偏りがあるとは判定しない。

初期化で形を非一様に作ること自体に事前補正は不要である。
ただし、逆算で引く自摸牌は手出し牌と別IDであっても同じ牌種でよく、その組合せを許す必要がある。
初期化の全再試行と時間を集計し、成立率が形の種類によって異なることを記録する。
この初期化を定常分布の標本やMHの提案に転用する場合は、別途確率補正が必要になる。

### 家別評価とフリテン

現在の[共同応答の解決](../tools/ev_policy_observation.py)では、非pass希望がなければ公開結果はpassになり、非pass希望があれば鳴きまたはロンを解決する。
今回の「副露と槓なしで続行した履歴」では全員パスに対応するため、相手の独立な希望確率の積を使える。
頭ハネや鳴き優先順位で複数の希望が同じ公開結果へ潰れる一般ケースを、このスコープへ持ち込む必要はない。

捨牌、同巡、リーチ後の各フリテンは、その家の仮説手牌と固定した公開履歴を時系列に評価して更新できる。
他家の実際の待ちを知る必要はない。
他家3人の事後分布は在庫制約で結合しているが、そのことは「変更された家の尤度だけを再計算する」を否定しない。
共有プールの整合と公開情報の不変性も同時に守ることが条件である。

### θ診断と予算の追補

較正期間でβを推定することは、診断用の代替モデルを構成する用途なら許容できる。
補正後の適合や事後差を、独立な性能改善の証拠と呼ばない扱いを維持する。
最適化範囲、正則化または境界、対象窓の支持件数、温度との適用順序、推定失敗時のholdをmanifestに固定する必要がある。
確認期間の層別結果を見て追加した診断なので、後にその期間を独立な採用判定へ再利用することもできない。

予算について、最小格子だけで14,720,000反復、同じ鎖のprefixを再利用して160,000まで走らせる場合で235,520,000反復になる。
格子を独立に走らせるなら、合計は309,120,000反復である。
単一の直列実行で一様な所要時間と仮定すると、24時間に収めるための1鎖10,000反復の平均時間は、最小格子だけなら58.70秒、最大格子までのprefix再利用なら3.67秒以内となる。
これは共有キャッシュ、並列化、初期化時間を含まない予算換算であり、実測速度ではない。

各反復には多数のM1、M2があり、M2は前後でVを列挙する。
マイクロベンチマークはこの列挙まで含める必要がある。
窓キャッシュにはLRU等の上限を置き、プロセス単位4 GiBとは別に並列数と総メモリ上限を固定する。
初期化の試行回数または時間上限と、10,000→40,000→160,000を延長するのか独立実行するのかも未定義である。
予算を超えたら設計へ戻る方針は妥当であり、結果を見て判断やシナリオを減らす退避策を用意する必要はない。

## 付録A. 国士成分の再現コード

プロジェクト直下で、以下をPythonへ標準入力で渡す。

```python
from tools.ev_calibration_state import shanten, TERMINAL_HONORS

base = tuple(int(i in TERMINAL_HONORS) for i in range(34))
states = {base}
for missing in TERMINAL_HONORS:
    for pair in TERMINAL_HONORS - {missing}:
        x = list(base)
        x[missing] -= 1
        x[pair] += 1
        states.add(tuple(x))

checks = legal = escaped = 0
for x in states:
    assert shanten(x, 0) == 0
    for old in range(34):
        if not x[old]:
            continue
        for new in range(34):
            if old == new or x[new] == 4:
                continue
            y = list(x)
            y[old] -= 1
            y[new] += 1
            y = tuple(y)
            checks += 1
            if shanten(y, 0) == 0:
                legal += 1
```

## 付録B. 提案比と合成核の再現コード

以下は麻雀局の実装テストではなく、設計と同型の固定位置交換による有限例である。
5物理ID、S={0,1}、S_r={0}、プール={2,3,4}、H(z)=[z0+z1<5]、目標質量`1+z0+2z1`を使う。

```python
import itertools
import numpy as np

states = [z for z in itertools.permutations(range(5)) if z[0]+z[1] < 5]
index = {z: i for i, z in enumerate(states)}
w = np.array([1+z[0]+2*z[1] for z in states], dtype=float)
pi = w / w.sum()

def swap(z, a, b):
    y = list(z)
    y[a], y[b] = y[b], y[a]
    return tuple(y)

def candidates(z, a):
    return [b for b in (1, 2, 3, 4) if swap(z, a, b) in index]

def kernel(kind, corrected=True):
    P = np.zeros((len(states), len(states)))
    for i, z in enumerate(states):
        if kind == 1:
            choices = [(a, b, 1/8) for a in (0, 1)
                       for b in range(5) if a != b]
        else:
            V = candidates(z, 0)
            if not V:
                P[i, i] = 1
                continue
            choices = [(0, b, 1/len(V)) for b in V]
        for a, b, q in choices:
            y = swap(z, a, b)
            if y not in index:
                P[i, i] += q
                continue
            j = index[y]
            ratio = w[j]/w[i]
            if kind == 2 and corrected:
                ratio *= len(candidates(z, a))/len(candidates(y, a))
            alpha = min(1, ratio)
            P[i, j] += q*alpha
            P[i, i] += q*(1-alpha)
    return P

A, B = kernel(1), kernel(2)
for name, P in [('M1', A), ('M2', B),
                ('M2_no_correction', kernel(2, False)),
                ('mixture', (A+B)/2), ('sweep', A@A@B)]:
    flow = pi[:, None]*P
    print(name, np.max(abs(pi@P-pi)), np.max(abs(flow-flow.T)))
```
