# フェーズD.3.2 相手行動モデル学習・較正レポート

## 結論

D.3.1の2,085,155教師窓を使い、全選手共有の階層付き条件付きsoftmaxを学習した。
D32-01の合法集合正規化と解析勾配、D32-02の共同応答尤度の全列挙一致は固定テストを通過した。
正則化選択、phase別温度較正、期間別の全件評価も完走し、保存モデルを再読込した評価値はfit時と完全一致した。

ただし、このモデルはD.3.3へまだ採用しない。候補別の厳密な受け入れを高速に計算する特徴が未実装であり、
合法和了の見送り、搶槓応答、大明槓には識別に十分な教師がなく、応答率にも較正不一致がある。次の作業単位をD.3.2aとして、このholdを先に解消する。

## 実装したモデル

- 行動種別と具体行動を分ける二段softmax。候補数の多さを種別確率へ直接足さない。
- 合法手にだけ確率を置き、一択の合法集合は厳密に確率1とする。
- 自己行動は正確な行動NLL、応答行動は公開結果と両立する全共同希望の周辺尤度を使う。
- ポン等で下位希望が隠れた家をpass教師にせず、両立するchi・pass等をすべて足す。
- 2018-19〜2022-23で学習し、2023-24で正則化を選び、2024-25で温度を較正した。
- 2025-26は開発確認にだけ使い、独立テストとは扱わない。
- 学習率0.03、batch 256、2 epoch、seed 20260909を学習前のmanifestへ固定した。

## 未識別成分と特徴hold

- `ron_pass`: 合法ロンを選ばなかった正確な観測は全期間で17件。暫定診断30件未満のため`opponent_component_unidentified`。
- `tsumo_pass`: 合法ツモを選ばなかった正確な観測は13件。同じ理由で`opponent_component_unidentified`。
- `chankan_response_policy`: 全364窓で非pass合法手がなく、informative窓0件。`opponent_component_unidentified`。
- `daiminkan_policy`: 観測は全期間32件だけで、期間別の予測率も不安定。`opponent_component_unidentified`。
- `exact_candidate_ukeire_not_implemented`: 候補別シャンテンは実装したが、候補ごとに34種を再計算する厳密受け入れは実行時間が大きい。現在は局所連結度を別名の補助特徴として使い、厳密受け入れの代用とは扱わない。

見送り13件・17件を増幅するoversamplingや、搶槓passを成功率0のron教師へ読み替える処理は行っていない。
ラベル定義`joint-public-resolution-v1`の変更は不要と判断した。
