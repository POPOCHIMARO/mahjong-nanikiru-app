# フェーズD.3 相手行動と履歴から局収支を推定する設計

作成日：2026-09-07。設計：Astra / high。
状態：D.3.0実装済み。次の実装単位はD.3.1。
本書は [Dの上位設計](PHASE_D_DESIGN.md) の7節を具体化する。
開発用設定の正本は [D.3開発計画](d3-development-plan.json) とし、採用条件や将来評価の凍結台帳とは分ける。

## 1. 作業契約と採用方針

今回の完了条件は、観測と情報境界、学習の尤度、世界の対象分布と提案分布、失敗時の扱い、実装順序、受入試験を定義し、文書と開発計画の整合検査が通ることである。
変更対象は本書、開発計画、関連設計の案内、README、既存プレイブックとする。
実行コード、原牌譜、C/C.1モデル、D.1生成物、D.2cの実測JSON、将来評価予約台帳は変更しない。
設計作業での隣接リスクは、デバッグ基盤の検証を予測性能の検証と混同すること、観測不能な行動を教師にすること、失敗試行を除いた平均をEVと表示することである。

採用する構成は、合法行動に確率を付ける小さな相手モデルと、配牌から判断時点までを復元する粒子法である。
麻雀固有の重みは本書で定義し、汎用粒子法ライブラリへ隠さない。
既存NumPy、標準ライブラリ、固定したmahjong 2.0.0を使い、新しい学習基盤はD.3の必須条件にしない。
実行環境と依存の実バージョンは実装時のmanifestへ記録する。

到達可能な状態は最大でも`exploratory_policy_model`である。
アプリ採点への採用、観測予測の合否、モデル誤差を含む同時区間はD.4以降に残す。
十分な世界を生成できなければ`held`で終え、完成した予測器としてD.4へ渡さない。

## 2. D.2cから引き継ぐ前提と不足

2026-09-07にコードと保存済み結果を確認した。
以下は今回発見した接続上の不足であり、本設計で修正を実施したという意味ではない。

| 対象 | 現在確認できたこと | D.3へ進むための処置 |
|---|---|---|
| `verify_policy_replay` | D.1と同じ`extract_round`による再生成一致。`RoundState`を通さない | スナップショットの再現性として保持し、実行器との独立なイベント照合を追加 |
| D.1母集団 | 35,218判断中、南4局以降が3,199判断（うちprimary 1,278）。南3局以前は32,019判断 | D.3入口で`kyoku >= 7`を隔離。D.1のIDや過去集計は上書きしない |
| 初期状態 | D.1には自家の過去ツモ列、応答時の判断履歴がない | 時点t以前の公開履歴と自家私有履歴を別レコードへ抽出 |
| 合成世界 | リーチ手をテンパイに条件付けない。一発などの履歴も再構成しない | D.3の事後分布から状態を構築し、リーチ時手牌と履歴フラグも持つ |
| 方策の危険度 | D.2cは`dangerLevel`の順位値。上位仕様は旧表の危険率とその和 | 旧`DANGER_RATES`の率を固定版へ投影し、現物の時系列判定を追加 |
| 行動表現 | `tile34`と赤区分だけでは、同じ通常牌の手出しとツモ切りが区別できない | 対外的に見える`origin`を追加。物理IDは渡さない |
| 試行失敗 | `evaluate_synthetic_debug`は成功試行だけの平均も返す | D.3では正の重みを持つ試行の実行失敗が一つでもあれば判断全体をhold |
| エラーと合法手 | `_score_ron/_score_tsumo`は`HandScoringError`を包括して不合法へ変換する | 役なし等の不合法と、依存不備、未対応裁定、状態破損を区別する |
| 鳴き後の方策入力 | `round_player_view`は通常自摸後だけを受け付け、受け入れは門前用 | 全進行phaseの視点、固定面子数を用いた評価を整備 |

従来の「D.2c完了」はデバッグ基盤と抽出器の再現性が完成したという範囲に限定する。
V01の実行器によるイベントと点差の一致、年度別ルール適合まで完了したと解釈しない。
前提を補う作業はD.3.0として実装し、D.2cの過去結果やハッシュを付け替えない。

## 3. 情報境界と学習データ

予測対象の入口は上位設計どおり、自家通常ツモ後、ツモ前1シャンテン、全家に既存の副露と槓なし、自家未リーチ、成立済み他家リーチ一名、南3局以前とする。
開始後の鳴き、槓、追加リーチは同じ試行内で扱う。
D.1候補は探索対象の参照であり、新実行器の合法行動と照合してから使う。
差があれば当該判断を隔離し、実選択が不都合だったことを採否理由にしない。

相手の学習用母集団はD.1の35,218判断に限定しない。
配牌直後からの四家の自摸後、鳴き後、捨牌応答、搶槓応答を旧期間の原牌譜から抽出する。
開始前の行動を世界推定へ使い、開始後の開いた手や高シャンテンの行動も生成するためである。
未来に副露があった局だけを落とす処理は禁止する。

| レコード | 内容 | 利用者 |
|---|---|---|
| `public-events` | 自摸の家と発生、捨牌の牌種と赤とorigin、宣言予定と成立、成立した鳴き、槓、ドラ公開、点棒 | 全家。自摸牌の牌種は公開されるまで伏せる |
| `private-events(seat)` | 当該家の配牌、過去と現在の自摸、本人が知る応答履歴、フリテンの状態 | 当該家の視点構築だけ |
| `teacher-windows` | 行動時点の各家自身の視点、合法手、観測ラベル集合、打ち切りマスク | 学習専用。予測入力APIから読めない |
| `inference-prefix` | `public-events[:t]`と対象家の`private-events[:t]`、目標スナップショット | 世界推定。t以後の配列や教師用他家手牌への参照を持たない |
| `observed-outcomes` | 実選択、局末結果、再構築した点差、教師用待ち | 後段の評価だけ。入力生成が終わった後にIDで結合 |
| `manifest` | 出典、対局単位分割、対象期間、ハッシュ、理由別件数 | CLIと監査。方策引数に入れない |

`DecisionView`は公開状態、自家の手牌と私有履歴、本人が分かるフリテン、進行phase、合法な意味上の行動を持つ。
本人に見えない山、他家手牌、裏ドラ、実際の未来、選手名、出典ID、世界seedを持たせない。
合法手の計算も本人の情報だけで可能な判定を使い、未公開裏ドラで和了や待ちの候補を変えない。
得点器による依存エラーが合法行動の欠落に見える経路をテストで塞ぐ。

教師用手牌は、その行動より前の配牌と自摸から復元する。
最終開示手牌を使って過去の欠損を補った特徴を通常教師として採用しない。
ラベルが曖昧なら`unknown`を残し、可能な他の学習headまで局ごと破棄しない。
初期手牌不正は局頭から、後続の復元不正はその位置以降だけを隔離する。

全新CLIは`select_development_inputs`とD.1 manifest照合を必須にする。
任意のdataset-dirを指定しても2026-27や未指定シーズンは読まない。
出典パスは許可manifestに一致するファイルだけに解決する。

## 4. 原牌譜と実行器の照合

D.3.0はまず牌譜tokenをイベント列へ変換するアダプターを作る。
既存の牌変換とtoken解析を再利用し、シャンテン候補の全列挙を毎回再計算しない。
アダプターと`RoundState`は別の境界を持ち、アダプターが出した観測イベントを実行器へ順に適用する。

原牌譜で実際に記録された配牌、通常自摸、嶺上、打牌、鳴き、公開ドラを制約として136牌を配置する。
未記録の位置には任意の整合的な補完を置けるが、未検証位置と明示し、終端以後へアクセスしない。
複数の補完で記録済み遷移が変わらないことを検査する。
他候補の未来へ記録イベントを貼り付ける用途では使わない。

物理IDそのものは原牌譜と比較できないため、牌種、赤、手出し／ツモ切り、所在、成立した行動、点棒を比較する。
符翻は原本に独立に保存された値または手計算fixtureと照合する。
得点器から作った期待値を正解として再読込するテストにしない。
本場、宣言成立、供託支出を含めた持ち点差と、局末精算だけの差を分ける。

未観測のロン見送りと競合した鳴き希望は、複数の履歴が可能である。
解決済みの公開結果が同じでもフリテン等の内部状態が異なれば候補状態を保持する。
保存上限を超えた場合は`ambiguous_response_history`とし、どれか一つを真値と認定しない。
任意の一状態で通っただけではV01全体をpassにしない。
最終得点、年度別ルール、未観測応答は別々の検証率を報告する。

## 5. 行動表現と相手行動モデル

### 5.1 意味上の合法手

通常自摸後は`discard`、`riichi_discard`、`ankan`、`kakan`、`tsumo`を扱う。
鳴き後は合法な打牌、捨牌応答は`pass`、`ron`、`chi`、`pon`、`daiminkan`、搶槓応答は`pass`と`ron`を扱う。
同じ通常牌の物理コピーによる重複は除き、赤の消費組合せは区別する。
打牌には`origin=drawn|concealed`を加える。
同じ牌種と赤の牌をツモと手中に一枚ずつ持つときも、公開される手出し情報が違うため学習上は別行動とする。
その後に実行器が該当する物理IDを解決する。

候補集合はphase全体で完成してから確率を付ける。
槓を生成できない版で槓確率を0と置いたモデルを本版として扱わない。
合法手が一つなら確率1、集合が空なら状態不正として停止する。

### 5.2 階層付き条件付きsoftmax

最初のモデルは、行動種別kとその具体的な行動aの二段階にする。
初版は選手間で係数を共有し、匿名の対局状況に対する行動分布とする。
潜在的な打ち手タイプや選手別埋め込みを同時に導入しない。

```text
K(v) = 視点vで合法な行動種別
A_k(v) = 種別kの意味上の合法行動（物理コピーの重複なし）
Pθ(k | v) = softmax_k(uθ(v,k) / T_phase)
Pθ(a | k,v) = softmax_a(sθ(v,a) / T_phase)
Mθ(a | v) = Pθ(k(a) | v) Pθ(a | k(a),v)
```

`u`と`s`は正則化付き線形スコアとし、種別headと具体牌headを分ける。
種別特徴は該当候補のシャンテン最小値、受け入れ最大値など固定集約も使う。
候補数そのものが多い種別を無条件に優遇するsoftmaxにしない。
温度Tはphase単位、初期値1とし、2024-25の観測尤度で較正する。

特徴は自家手牌、固定面子数、シャンテン、公開残存枚数による受け入れ、ドラ保持、手出し／ツモ切り、役の手掛かり、複数リーチへの危険度、河の時系列、巡目、残り山、親子、本場、供託、点差、局番号とする。
鳴き後の受け入れは固定面子数を渡して計算する。
槓後の未知の嶺上や新ドラを覗いた特徴を作らない。
役なし、フリテン、ルール上の和了可否は合法手の境界で扱う。

損失は「正確に分かる選択」の負の対数尤度と、次節の打ち切られた応答の負の対数尤度の和にL2正則化を加える。
母集団の行動率を変えるクラス均等化や希少クラスの無補正oversamplingはしない。
固定された同一窓には重み1を与え、非識別なheadはマスクする。
最初は全窓を逐次処理し、メモリに全候補行列を保持しない。
正則化候補は0.01、0.1、1、10、100とし、2023-24の窓当たり負の対数尤度で選ぶ。
optimizerはNumPyによる決定的minibatch更新とし、解析勾配を有限差分で検査する。
学習率、epoch上限、seedを学習前にmanifestへ固定し、同じ窓集合と評価方式で比較する。

### 5.3 優先順位で隠れる応答

三家の応答を、同じ公開状態で互いの希望を見ずに生成する。
各家の確率は自家視点に条件付け、共通の世界の下で独立と仮定する。
この条件付き独立と選手差の省略はモデル仮定であり、実戦の事実とはしない。

```text
c = (c1,c2,c3)                    # 各応答者の希望
R(x,c) = 優先順位で解決した公開結果
C(x,y) = {c : R(x,c) が観測yと一致}
Lθ(y | x) = Σ[c∈C(x,y)] Π[j∈responders] Mθ(cj | view_j(x))
loss_response = -log Lθ(y | x)
```

例えば、ポンが成立しても、優先順位で負ける家がチーを希望したかどうかは分からない。
その家をpassの教師にせず、観測と両立する希望の確率を足す。
誰も鳴かず次の自摸が来た窓では、合法な非pass希望が必ず成立するルール範囲なら全員passと分かる。
頭ハネされた他家のロンを「見逃し」と認定しない。
全組合せは意味上の行動に縮約して正確に列挙する。
列挙上限で切り詰めて再正規化する処理は入れない。

希望の集合から次状態が一意でなければ、世界推定では確率に従って潜在希望もサンプルして状態へ反映する。
教師復元ではフリテンの未確定履歴を保持し、合法集合が変わる窓のheadをマスクする。
既知のツモ打牌headまで破棄しない。
不確定な応答履歴を点推定で補って、正解ラベルとして学習するEM処理は初版に入れない。
このマスクによる欠測は無作為とは仮定しない。
確定窓だけで学習した成績はその範囲の値として報告し、曖昧窓の多い層への外挿は未検証とする。

相手については合法和了でもpassや別行動へ正の確率を持てるようにする。
自家の比較方策は仕様どおり合法和了を必ず取る。
相手の和了見送りは希少で、優先順位の打ち切りもあるため、十分な教師がなければ識別できない。
その場合は`opponent_component_unidentified`を報告し、常時和了や小さい見送り率を置いたものは別名の感度シナリオとする。
無観測の行動を成功率0やルール上不可能と同一視しない。
学習値を採用できる支持件数と区間幅はD.3.2で診断し、採用閾値はD.4で固定する。

## 6. 履歴に条件付けた世界の分布

### 6.1 推定対象

`I_t`は対象家の初期手牌、時点tまでの私有履歴と公開履歴であり、初手aを選ぶ直前に確定する。
対象家の過去の行動は、その家がすでに知る情報によって選ばれた既知の操作として扱う。
未知の他家手牌を対象家の実選択らしさで重み付けし直さない。
これは対象家の全私有情報を視点へ含めるというモデル仮定に依存する。
相手の過去行動は未知手牌の情報を含むため、その尤度を使う。

`x_e`は配牌からイベントeまでの四家の手牌、未割当牌の多重集合、牌位置の予約、非公開の自摸と応答履歴を含む。
対局開始時の事前分布`p0`は136枚の公平なシャッフルと固定した配牌順とする。
同じ通常牌の個体名は周辺化し、赤と通常を分けた37カテゴリの残数を持つ。
次の未知牌がカテゴリcである確率は`n_c / N_remaining`である。
相手の13枚の配牌は残数から無作為非復元抽出し、牌姿を選り好みしない。

```text
γ_t(x_0:t, c_1:t)
  = p0(x0 | 対象家の配牌, 最初の公開ドラ)
    × Π[e=1..t] F_e(x_e | x_<e, c_e)
    × Π[e=1..t] H_e(I_t, x_0:e, c_e)
    × Π[相手の自己行動e] Mθ(a_e | view_actor(x_<e))
    × Π[応答窓e, 相手j] Mθ(c_ej | view_j(x_<e))

Bθ(x_0:t,c_1:t | I_t) = γ_t / Σ γ_t
```

`F_e`は牌を戻さない抽出とルール遷移、`H_e`は観測された牌、手出し、宣言、公開結果、自家私有情報との整合指示子である。
ここで`c_e`は応答窓では三家の希望、自己行動窓では当該家の行動を表す。
`F_e`には相手の選択確率を含めず、`Mθ`と二重に掛けない。
上式は自摸と選択を別イベントで記述したもので、選択直前の視点にはその家の今回の自摸を含める。
自家の応答が観測または本人の履歴から確定する場合は既知操作とし、その相手モデル尤度を掛けない。
未観測で推定対象にする自家応答が残るなら、私有履歴不足をholdにするか、明示した観測モデルの別版を必要とする。
相手の見送りによるフリテンは潜在履歴の一部として更新する。
局末結果やtより後の他家の開示手牌は`H_e`に入れない。

成立済みリーチは、宣言時に合法なテンパイだったこと、宣言牌の応答を通過したこと、その後の合法行動履歴を硬い制約にする。
河に待ちがあるフリテンリーチは合法であり、それだけで棄却しない。
対象家の実際の初手や候補ごとに`Bθ`を作り替えない。

### 6.2 牌山を遅延生成する表現

全ての山順を最初から固定してから観測牌を偶然引く方式は、私有自摸一枚ごとに粒子が失われやすい。
そこで未観測位置への割当は遅延し、実際に必要になった位置に残数比例で牌を割り当てる。
嶺上4位置、表5位置、裏5位置、生牌位置を別に予約し、同じ牌を二度使わない。
初期ドラは表5位置のうちの一つであり、追加の15枚目の王牌を作らない。
これは公平な無作為順列の部分的な公開と等価な表現であり、未知山を任意に並べ替えて観測へ合わせる修復ではない。
既に引かれた非公開自摸も粒子内では値を保持する。
今後の鳴きで手番が変わっても、共通の生牌列の位置を進める。

判断時点で残る未割当位置を同じ条件付き残数から一度だけ埋め、D.2の136牌状態へ変換する。
全初手候補でその世界を共有する。
他家のリーチ時手牌、二重リーチ、一発、見送りフリテンも粒子の履歴から渡す。
状態を作るたびにそれらをfalseへ初期化しない。

## 7. 基準となる粒子アルゴリズム

### 7.1 観測を使う提案と重み

最初は正確に列挙できる一イベントの遷移を使う。
一イベントは未知自摸と直後の自己行動をまとめられるが、途中で公開される情報の順序は保存する。
自摸牌の最大37カテゴリと意味上の合法行動、応答の有限集合を列挙する。
対象家の既知自摸はそのカテゴリへ強制できるが、残数の確率を重みに残す。

```text
K_e(x',c | x,y_e) = F_e(x',c | x) × H_e(y_e,x',c) × M_e(c | x,x')
G_e(x) = Σ[x',c] K_e(x',c | x,y_e)
q_e(x',c | x,y_e) = K_e(x',c | x,y_e) / G_e(x)

非再標本化時: w_e(i) = w_(e-1)(i) × G_e(x_(e-1)(i))
再標本化直後: 各旧重みを1/Nとした上で同じ更新
```

`M_e`は一イベント内の各選択直前に構成した自家視点から計算する。
自摸と打牌をまとめた場合は自摸後かつ打牌前の視点を使い、イベント終端の手牌や結果を特徴へ入れない。
自己操作だけの窓では対応するモデル確率を1とする。
初期提案は`p0`そのものなので初期重みは一様である。
初期配牌の提案を別分布に変える場合は初期にも`p0/q0`が必要になる。

例として未割当N枚中cがn枚あり、対象家の次の自摸がcと既知なら、提案はcを確率1で置き、重みには`n/N`を掛ける。
ここを1にすると、自家の観測自摸と矛盾しやすい相手手牌が過大に残る。
他家の捨牌が手中にない粒子では、直前の未知自摸でその牌を得た可能性も列挙し、origin制約を同時に検査する。

一般の別提案qへ拡張する場合の増分重みは`K_e / q_e`である。
硬い制約を満たす経路でqだけが0になる提案は不可とする。
受理できるまで繰り返してから成功数だけで正規化する方式は、切断分布の確率を失うため使わない。
`G_e=0`の粒子は重み0とし、全粒子0なら数値を返さない。

重みはlog空間、正規化はlog-sum-expで計算する。
正規化重みをWとすると`ESS = 1 / Σ_i W_i²`とする。
基準版の正規化定数は各段の`Σ_i W_(e-1)(i) G_e(x_(e-1)(i))`の積で推定し、log値で保持する。
ESSがN/2を下回ればsystematic resamplingを行う。
その直前のESS、最大重み、祖先の多様性を記録する。
再標本化直後の一様重みを「N個の独立な世界が得られた」証拠にしない。
粒子法の一般形、観測を使う提案、退化の注意は [DoucetとJohansen](https://www.stats.ox.ac.uk/~doucet/doucet_johansen_tutorialPF2011.pdf) を参照した。
上記の麻雀イベントへの写像と観測境界は本プロジェクトの設計であり、この資料で検証された結果ではない。

### 7.2 退化と改良の境界

この一段先の提案でも、リーチ宣言に至る手牌が粒子に残らない可能性がある。
再標本化だけでは、失われた配牌や過去自摸の組合せを復元できない。
そのため基準版を実装しただけで、実牌譜全体に十分な推定能力があるとは認定しない。

基準版は有限小例の正しさを検査する参照実装とし、実牌譜の適用率をD.3.3で測る。
粒子数は256、1,024、4,096の開発用格子とし、各設定4独立反復を用意する。
この数は性能保証や採用閾値ではない。
EVが好都合だった反復だけを選ばず、予定した反復が一つでも失敗した設定はholdにする。
粒子数変更は診断と固定予算に基づき、予測結果の符号で決めない。

改良候補は、配牌と過去の非公開自摸を含む短いブロックのresample-moveである。
導入時は、履歴込みの対象密度γ、逆向き提案密度、次の受理率を実装可能な形で定義し、有限小例で詳細釣合いを検証する。

```text
α(x,x') = min(1, γ_e(x') q_move(x | x') / (γ_e(x) q_move(x' | x)))
```

変更した区間以後は牌保存、合法性、他家行動の尤度、フリテン履歴を全て再計算する。
テンパイ手だけの差替え、対称性が不明な交換、重みを伴わない学習済み手牌生成器を導入しない。
具体的なブロック提案は基準版の退化位置を見て設計するため、今回の実装契約には含めない。
基準版の適用率が不十分ならD.3.3を探索試作として止め、Astra/highでこの提案を追補する。

### 7.3 必須診断と保留

各イベントで、ESS、最大正規化重み、重み0の原因、直前と配牌時の祖先数、リーチ者の手牌signature数、再標本化回数を保存する。
signatureは牌種と赤と必要な履歴状態から作り、通常牌IDの違いを多様性に数えない。
各独立反復の待ち牌確率、フリテン率、手牌ドラ分布、正規化定数の推定値、後続局収支を比較する。
有限小例では正規化定数と事後分布そのものを列挙正解へ照合する。

`posterior_zero_mass`、`posterior_unstable`、`private_history_missing`、`rule_unresolved`、`opponent_component_unidentified`、`resource_budget_exceeded`は別理由にする。
数値アンダーフローと、本当に合法な整合経路がないことも区別する。
未観測の待ちや未来結果を見て粒子を選び直さない。
一様世界への退避は禁止する。

D.3.3実牌譜pilotでは適用率、失敗位置、層別の欠測率を先に報告する。
予測採用に必要なESS、多様性、反復間差の閾値は現在未確定で、開発計画ではnullを保つ。
未確定のまま「診断合格」を返すAPIは作らない。
診断が悪い局面を取り除いた集合だけで全体性能を宣伝しない。

## 8. 全候補の前向きシミュレーション

初期の事後世界と重みは、判断ごとに一回だけ作る。
自家の各初手と継続方策を全て同じ世界で走らせ、以後の相手は各自の視点でMθから行動する。
初手ダマは一打だけの指定であり、その後のpushは合法ならリーチする。
自家は押しとオリの両方で合法和了を取り、自分から鳴きと槓をしない。

旧危険率、時系列の現物判定、origin解決を整備した継続方策は`closed_push_v2`と`closed_fold_v2`にする。
現行v1は過去デバッグの再現用に保存する。
v2で同じ意味の打牌に複数originがあれば、未リーチでは手中牌を優先し、成立後はツモ牌だけとする。
この選択を物理IDの最小値に依存させない。
push初手ではテンパイと1シャンテン、赤と通常、リーチとダマを区別し、fold初手では形を崩す打牌を含める。

現物は本人の全河に加え、成立済みリーチに対して確実にロン権がなくなる時系列の通過牌を扱う。
複数リーチでは安全性を各家別に評価し、リーチ前に他家が捨てただけの牌を自動で現物にしない。
この仕様の裁定が未確定ならv2の固定例を保留し、危険率を推測して完成扱いしない。
旧表の率は守備の並べ替えにだけ使い、実際の放銃確率を別途差し引かない。

生牌列と王牌は初期世界で固定し、鳴き後の家と牌位置はルールから決まる。
分岐後の行動乱数は、runSeed、世界番号、反復番号、相対家、phase、当該家の意思決定回数、用途からSHA-256で安定生成する。
候補ID、worker番号、列挙順、Pythonの組込hashをseedの成分にしない。
同じキーの一様乱数を各分岐の合法行動分布の逆CDFへ与える。
鳴きで局面が異なれば選択が違うことは正常であり、実牌譜の未来列へ同期させない。

```text
Q_hat(a,π) = Σ_i W_i × (1/K) Σ_k R(i,k,a,π)
paired_delta(i,k) = R(i,k,a,π) - R(i,k,b,ρ)
```

`R`は判断直前点から局末点への差であり、途中のリーチ支出も含む。
人工的撤退コスト、順位点、次局価値は足さない。
和了収入、放銃、被ツモ、その他家同士のロン、聴牌料、供託の支出と獲得をイベント台帳へ分け、合計が点差と一致することを検査する。

有限粒子の重み付き平均を不偏EVとは呼ばない。
初期世界を固定した後のモンテカルロ誤差と、世界推定の反復差を別に報告する。
再標本化の祖先が共通の粒子を独立観測として標準誤差を計算しない。
標準誤差は独立な全パイプライン反復の候補別平均とpaired差から計算し、少なくとも4反復を必要とする。
これは固定モデルに対する数値計算のばらつきであり、学習誤差を含む最終95%区間ではない。
max候補の選択後区間と採点用の同時区間はD.4の対象である。

重み0の粒子を事後分布から除く処理と、正の重みの将来試行が失敗した処理を区別する。
後者は候補別の成功平均だけを返さず、判断の比較値、順位、区間を全てnullにしてholdにする。
成功試行の生ログはデバッグ用に残せるが、予測値欄へ転記しない。
依存版の確認と既知の得点fixtureを実行前に検査し、試行途中で依存が欠ける経路を防ぐ。

## 9. 観測予測の検証と期間分割

学習は2018-19〜2022-23、方式選択は2023-24、確率較正は2024-25、開発確認は2025-26とする。
同じ対局の全局、全家、全候補を同じ分割へ入れる。
2025-26は未使用の検証期間と呼ばず、新しい性能採用の証拠にしない。
学習に使った対局上の予測値は適合確認と表示し、方式選択や最終比較へ混ぜない。

相手モデルは自己行動のNLL、種別Brier、較正、鳴きと槓とリーチの率、層別欠測率を確認する。
打ち切られた応答は観測結果の尤度で評価し、他家の見送り正解率を捏造しない。
標準化係数と語彙は学習期間だけから作る。
ルール例外や低件数headを含むモデルは、その適用率と保留理由を保存する。

世界モデルは、公開前に予測した後続の公開イベントや、教師専用経路で復元した同時点の待ちを後から照合できる。
後者の他家手牌を初期化、粒子の救済、ハイパーパラメータの局面別選択へ戻さない。
裏ドラや未使用山は観測がないため正解率を出さない。
全保持データでの事後分布の較正と、SMCの数値精度を別に診断する。

観測局収支の経路では、初手だけ実選択へ固定し、その後の自家も観測行動モデルから進める。
push/foldを継続させた収支を実際の収支と一致させる評価にはしない。
実選択が2シャンテンへ崩す牌でも、Dの入口を満たしていれば観測経路へ残す。
同じD.3採用集合でC.1等の基準値を再計算し、異なる母集団のスコアを直接引かない。

## 10. 出力、計算予算、状態遷移

出力は次を必須にする。

```text
schemaVersion, estimand, scopeStatus, eligibleForAdoption=false
decisionId, informationStateHash, publicStateHash, privatePrefixHash
ruleVersion, policyVersions, opponentVersion, beliefVersion, featureSchemaVersion
modelManifestHash, codeManifestHash, inputManifestHash, dependencyManifestHash

candidateCoverage, pairedTrialKeys, eventLedger, candidates[Q, components, mcse]
particleDiagnostics, responseCensoring, runtime, holdReasons
```

私有prefixの内容は対象家だけとし、ハッシュにも未来や他家の教師データを入れない。
公開局面IDだけでは自家の私有履歴が違う入力を区別できないため、キャッシュ鍵に`informationStateHash`を使う。
コードmanifestはsimulation.py一枚でなく、実行器、得点器、特徴、ルール表、乱数仕様を含む推移的依存を対象にする。
各JSONの生成時に実際に読み込んだコードのハッシュを固定し、後から更新しない。

```text
synthetic_debug → 検証専用
held → 診断または部品未成立。EV/順位/区間はnull
exploratory_policy_model → 数値基盤と所定の開発診断を通過。採点は不可
frozen_candidate / validated_policy_model → D.4/D.5のみ
```

D.2cの実測は27候補、4世界で108試行、22.11秒だった。
同じ速度でも27候補×1,024世界は約94分になり、粒子法と学習相手の時間はこの外側に加わる。
初回から32,019判断の全候補評価を実行する計画にはしない。

最初の計算量pilotは、学習期間だけから公開情報で層化した16判断とする。
相手の待ち、結果、実打牌をサンプリング基準にしない。
先にID集合を固定し、失敗した判断を別の判断へ補充しない。
試行は粒子数256から始め、固定した計算予算を超えれば件数と理由を残してholdにする。
全件再現試験と全件シミュレーションを混同しない。
予測器は最初からオフライン処理とし、ブラウザ応答時間の目標は置かない。
進捗、処理済み件数、チェックポイントを一定間隔で出し、再開は同じmanifestでだけ許す。

祖先と手牌の多様性、独立反復、有限例の正解を併用し、それでも実牌譜上の精度を保証しない。
もう一つは「全件の再生成が一致したので実行器も正しい」という誤読であり、D.3.0で検証経路を分けて対処する。
