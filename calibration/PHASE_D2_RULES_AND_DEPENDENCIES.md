## 2. 参照元と版の扱い

規定の正本は[Mリーグ公式ルール](https://m-league.jp/about/)とする。
2026-09-07に取得したページのハッシュと依存の公開メタデータは[参照元記録](probes/rules-dependency-sources.json)に保存した。
HTMLはローカルの `calibration/.dependency-cache/` に保管し、Git管理から外した。
HTML全体のハッシュは取得物の識別用であり、ルール部分だけの意味的なハッシュではない。
ページから各年度の改定日や全履歴は確認できていない。

次の区分を使い、明文化された規定と実装上の解釈を混同しない。

| 区分 | 意味 | 扱い |
|---|---|---|
| 明記 | 現在の公式規定が直接指定する | 固定例の期待値にする |
| 解釈 | 明記された規定をイベントやアルゴリズムへ翻訳したもの | 根拠と反例を保存し、裁定資料が得られたら照合する |
| 未確認 | 歴史的適用や複数規定の優先関係を確認できていない | 確認済みと表示せず、予測評価の合格条件から隠さない |

D.1の `mleague-phase-d-v1` は局面抽出に必要な部分規則である。
D.2では `mleague-round-v2` を別IDで追加し、参照日、依存版、アダプター版、解釈項目を一緒に保存する。
旧IDの意味や既存JSONLを変更しない。
2018-19〜2025-26は開発許可期間であって、すべての規定が同じだったと確認済みの期間ではない。
原牌譜再現での一致はその実例の証拠にとどめ、出現しなかった稀な規定の歴史的同一性を証明したとは扱わない。
2026-27の牌譜は選定にも開発にも使用しない。

## 4. 得点計算の設定と補正

### 4.1 明示設定

公式の得点表には場ゾロ2翻が含まれているが、ライブラリへ渡す `han` は役とドラの翻数である。
場ゾロ2翻を追加して渡さない。
30符4翻と60符3翻は切り上げ満貫、役満以外は11翻以上を三倍満上限とする。
根拠は公式第6章3〜6条。

| ライブラリ設定 | 値 | 目的 |
|---|---|---|
| `has_open_tanyao`, `has_aka_dora` | `True` | 食いタンと各色1枚の赤5 |
| `has_double_yakuman` | `False` | 国士13面、四暗刻単騎、純正九蓮、大四喜の単独倍化を行わない |
| `kazoe_limit` | `HandConfig.KAZOE_SANBAIMAN` | 数え役満を採用しない |
| `kiriage` | `True` | 30符4翻と60符3翻を満貫にする |
| `fu_for_open_pinfu` | `True` | 食い平和形ロンを30符にする |
| `fu_for_pinfu_tsumo` | `False` | 門前平和ツモを20符にする |
| `limit_to_sextuple_yakuman` | `False` | ライブラリ独自の6倍上限を持ち込まない |
| `has_daisharin`, `has_daisharin_other_suits`, `has_daichisei`, `has_sashikomi_yakuman` | `False` | 対象外のローカル役を無効にする |
| `renhou_as_yakuman` | `False` | 人和自体は下記入力でも無効にする |
| `paarenchan_needs_yaku` | `True` | 設定を明示するが、八連荘入力自体を常に0とする |

`HandConfig` の `is_renhou`, `is_open_riichi`, `is_nagashi_mangan` は常に `False`、`paarenchan` は0とする。
`renhou_as_yakuman=False` だけでは人和を無効にしたことにならない。
役満の複合は有効とし、単独役の倍化とは区別する。
役名は公式第9章の採用役一覧へ対応づけ、ライブラリの名称だけで新しい役を有効にしない。
設定項目とAPIはwheel実体の `hand_config.py` と `hand.py` を確認済みであり、そのファイルハッシュは[選定実験結果](probes/mahjong-2.0.0-selection.json)に記録した。
固定した2.0.0には、公開リポジトリの後続版にある `is_three_player` と `num_nuki_dora` がない。
実装はwheelの配布メタデータで2.0.0を検査し、後続版の引数を渡さない。
四麻はDの状態型と34種136枚で固定する。

### 4.2 連風牌の雀頭2符

2.0.0の符計算は、自風と場風が重なる雀頭を4符にする。
公開オプションに2符への切替はなく、符計算器を注入するAPIもない。
そこで得点アダプター内で、次の条件をすべて満たしたときだけ計算用 `round_wind=None` とする。

1. 実際の自風と場風が同じ。
2. 和了牌と全副露を含む完成手の物理牌を一回ずつ数え、その風牌がちょうど2枚。
3. 牌保存と和了入力の妥当性が検査済み。

字牌は順子を構成しないため、この2枚は通常形で必ず雀頭になる。
七対子でも同牌の刻子役は成立しない。
2.0.0で場風が使われる箇所は雀頭符の対象と場風刻子役の判定であり、この条件では後者を失わない。
自風指定を残すため役牌雀頭2符と平和不成立を保ち、`is_dealer` の親子判定も変わらない。
風牌が3枚か4枚なら補正せず、連風刻子の2翻を保つ。
元のWorldState、PlayerView、実際の場風は変更せず、監査出力に実際の風と正規化理由を残す。

通常5のみの `111234m567p789s11z` を9sロン、東場の東家、リーチのみとした例では、未補正は1翻50符、補正後は1翻40符2,000点になる。
南場の南家で雀頭を南へ変えた例は1翻40符1,300点となり、両方を選定実験で確認した。
丸め済みの50符から2符を引いても40符にはならないため、戻り値の後処理で直さない。
依存更新時は場風の使用箇所を再点検し、通常形の複数分解、七対子、役満、刻子、槓子を含む回帰試験を必須とする。

### 4.3 牌IDと精算の境界

ライブラリも136形式を使うが、IDの一致だけを仮定せず、Dの `tile34` と赤区別を往復検査する。
通常5は赤牌IDの16、52、88へ割り当てない。
文字列fixtureには `TilesConverter.string_to_136_array(has_aka_dora=True, ...)` を使い、通常5を `5`、赤5を `0` と表す。
これを省くと、赤対応なしの変換が割り当てたIDを、赤対応ありの得点計算が赤と判定する。

和了入力の `tiles` には全副露と槓の4枚目も含め、和了牌を一度だけ含める。
各 `Meld` の牌はこの同じ集合への参照とし、合計枚数を二重に足さない。
ロンでは和了者用の計算集合へ放銃牌を一時的に加えるが、世界内の所在は一つのまま扱う。
裏ドラは成立済みリーチの和了計算時だけ、専用の `ura_dora_indicators` 引数へ渡す。

ライブラリ呼出しの `tsumi_number` と `kyoutaku_number` は0に固定する。
返り値の役、翻、符と本場なしの基本支払いを受け取り、自前の精算器だけが本場、責任払い、供託を適用する。
`ScoresCalculator` へ26翻を渡して64,000点になる検査は複合倍率の検査に限り、複合役の検出試験の代用にはしない。
未対応役や計算エラーは `unscorable` とし、役なしとライブラリ異常を別理由で返す。

### 5.1 D.1のリーチ判定を継続局へ広げる際の注意

D.1は通常ツモ直後だけを対象としたため、残り山0と海底ツモを同一視できた。
D.2では `draw_source=live/rinshan` と `is_last_live_draw` を持ち、海底禁止は後者で判断する。
門前の暗槓後に残り山が0になっても、その嶺上牌は海底牌ではない。
この嶺上後のリーチを許すことは「ツモ番不要、海底を摸した者だけ禁止」からの実装解釈とし、専用fixtureを置く。
`remaining_wall > 0` や `after_normal_draw` をそのまま継続局の全リーチへ適用しない。
嶺上和了では海底役を付けず、最後の捨牌へのロンでは河底を評価する。

### 5.2 フリテンとリーチ後暗槓の実装解釈

和了形の待ち集合と、役のある合法ロン集合は別に計算する。
役のない側の待ちを捨てている場合も捨牌フリテンを判定する。
同巡内も形を完成させる牌を見送った記録で更新し、チー／ポンを経た本人の打牌完了でも一時フラグを解消する解釈を採る。
この2点は公式の「アガリ牌」「摸打」の機械化であり、細部を明示した公式裁定は今回確認できていない。
合成fixtureの合格だけで裁定確認済みとしない。

リーチ後暗槓は待ち牌集合の一致だけでは不足する。
リーチ後13枚の各待ちについて全和了分解と和了牌の所属を列挙し、候補刻子がすべての分解で独立して存在することを要求する。
槓後はその槓子を同種刻子へ正規化し、雀頭、その他の面子、待ちの所属が元の集合と一致することを検査する。
役の増減だけでは拒否しない。
同じ待ちでも順子として使う分解が消える例は拒否する。
この比較の具体fixtureを確定する前に、待ち一致だけの近似判定を合法手生成へ入れない。

### 5.3 状態機械と合法手

進行は次の単位で処理し、一発やフリテン更新のタイミングを分散させない。

```text
DRAW → SELF_ACTION → DISCARD_RESPONSES
                     ├─ RON → SETTLEMENT
                     ├─ PON/CHI → CALL_DISCARD → DISCARD_RESPONSES
                     ├─ DAIMINKAN → KAN_COMMIT → RINSHAN_DRAW
                     └─ PASS → DRAW または EXHAUSTIVE_DRAW
SELF_ACTION → KAKAN_PROPOSE → CHANKAN_RESPONSES
                            ├─ RON → SETTLEMENT
                            └─ PASS → KAN_COMMIT → RINSHAN_DRAW
SELF_ACTION → ANKAN → KAN_COMMIT → RINSHAN_DRAW
```

各応答は同じ直前状態から全家の希望を集めて解決し、処理した家の順番で情報や権利が変わらないようにする。
頭ハネで不成立だった他家ロンは見送りと記録しない。局は勝者一人で終了する。
リーチ後は合法和了、ツモ切り、構成不変の暗槓だけを提示する。
自家のpush/fold方策が槓を選ばない制限は、実行器の合法手から槓を消す理由にしない。
生牌山が0なら新しい槓を開始できず、4回目の槓後でも王牌14枚と各牌一所在を検査する。
非法行動、チョンボ、発声時刻に依存する裁定を合法対局の乱数イベントとして生成しない。
原牌譜にそれらが含まれるときは、再現未対応の理由と出典を報告する。

## 6. 責任払いと点棒台帳

責任払いは公式第8章に基づき、大三元、大四喜、四槓子に適用する。
暗槓を含む公開済み面子を数え、該当役を確定させたポンまたは大明槓の成立イベントで責任者を保存する。
四槓子は4つ目の大明槓を対象にし、自分の暗槓や加槓で4つ目となった場合を責任払いにしない。
最終手牌だけを見て責任者を推定しない。

各役満成分の支払いを先に計算する。
責任対象成分はツモなら責任者が全額、第三者ロンなら責任者と放銃者が半額ずつ、責任者自身の放銃なら同人が全額を払う。
対象外の役満成分は通常のツモ／ロン精算とし、本場全額は責任者が一回だけ負担する。
供託は支払者から徴収せず、卓上残高から勝者へ移す。
公式掲載の大三元と字一色の複合例を独立の期待値に使う。
南家が西家の責任で1本場ツモの場合、東−16,000、西−40,300、北−8,000、南+64,300になる。

複数の別々の責任者が一つの和了に成立する場合の本場帰属は、現在の本文と掲載例だけでは確定していない。
役満成分ごとの責任者は保持できる設計にするが、本場の重複徴収や推測配分を実装しない。
この状態を検出した評価バッチは `hold: multiple_pao_honba_unresolved` として報告し、試行だけを捨てて残りの平均EVを採用しない。
解消まではD.2全域のルール検証完了を宣言しない。

局収支の起点は判断直前の持ち点と供託である。
起点以前のリーチ支出をもう一度引かない。
すべての遷移で `sum(scores) + 1000 * kyotaku` を保存し、局末で各家の内訳合計を持ち点差に一致させる。
流局では供託を持ち越す。
Dの初期対象から南4局以降を外す既存方針を維持し、終局トップへの供託分配や順位点を局EVに混ぜない。

## 9. 実施した検証

[選定実験スクリプト](probes/probe_mahjong_2.py)をPython 3.12.14で実行し、16項目すべて成功、exit 0。
[結果JSON](probes/mahjong-2.0.0-selection.json)には入力wheelと計算ソースのハッシュ、期待値、実測値を記録した。
これはD.2本体や全ルールの検証合格を示さない。
選定スクリプトはダウンロードせず、ネット接続なしで再実行できる。

```powershell
python calibration/probes/probe_mahjong_2.py calibration/.dependency-cache/mahjong-2.0.0-py3-none-any.whl --output calibration/probes/mahjong-2.0.0-selection.json
```

懐疑的なレビューでは「連風補正が場風役を落とさないか」が主な論点になる。
完成手全体で2枚の場合に限ることで刻子成立との両立を排除し、親子を決める自風を保持した。
通常牌5と赤牌IDの不一致は実験で検出し、変換オプションの明示と専用2検査で修正した。
本番アダプターでは、この小規模実験に加えてS04とS07の分解境界を検証する。
